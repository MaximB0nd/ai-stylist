# AlbumService — контракт и логика модуля

Документ описывает существующую реализацию Backend Core проекта AI Stylist, проверенную 17.10.2026. Исходный файл: `src/backend_core/app/services/album_service.py`, исследуемый commit: `791e71c5c0b7c4bc06a2d9e98a9dcf2f0b5ebcb6`.

## Назначение и границы ответственности

`AlbumService` получает сведения об альбомах, проверяет принадлежность запрошенного альбома пользователю и формирует DTO ответа. Изображения не загружаются в память сервиса: в ответ включаются ссылки на объекты хранилища.

Модуль не проверяет JWT, не выполняет SQL самостоятельно, не создаёт альбомы, не запускает генерацию и не загружает или удаляет фотографии. Аутентификация выполняется до его вызова, чтение данных — репозиторием, формирование S3-подписи — хранилищем.

## Зависимости и точка сборки

```python
AlbumService(
    album_repo: AlbumRepository,
    storage: StorageService,
)
```

Зависимости сохраняются в экземпляре; конструктор не выполняет ввод-вывод. Их жизненным циклом управляет вызывающий код. В приложении сервис создаётся функцией `get_album_service` в `app/core/dependencies.py`: репозиторий получает сессию БД запроса, хранилище поступает из провайдера зависимостей.

Потребители — обработчики в `app/api/v1/endpoints/albums.py`:

- `GET /api/v1/albums/{album_id}` вызывает `get_album`;
- `GET /api/v1/albums` вызывает `get_user_album_ids`.

Дополнительные зависимости модуля: схемы Pydantic из `app/schemas/album.py`, исключения FastAPI, `asyncio` и `uuid`.

## Получение альбома

```python
async def get_album(
    self,
    album_id: uuid.UUID,
    current_user_id: uuid.UUID,
) -> AlbumDetailResponse:
    ...
```

### Вход и предусловия

- `album_id` — UUID запрашиваемого альбома.
- `current_user_id` — UUID пользователя, установленного аутентификацией. Передавать сюда произвольный идентификатор из пользовательского запроса нельзя.
- Репозиторий реализует асинхронную операцию `get_by_id_with_photos(album_id)`, возвращающую альбом с загруженной коллекцией фотографий либо `None`.
- Хранилище предоставляет синхронную операцию `presigned_public_url(object_key) -> str`. Если этот атрибут отсутствует, используется `presigned_url(object_key)`.

Аннотации UUID сами по себе не выполняют проверку при прямом Python-вызове. На HTTP-границе формат идентификатора проверяет FastAPI.

### Последовательность выполнения

1. Получить альбом через `album_repo.get_by_id_with_photos`.
2. Если результат отсутствует, выбросить ошибку 404.
3. Сравнить `album.user_id` и `current_user_id`; при несовпадении выбросить ошибку 403.
4. Выбрать операцию хранилища для формирования ссылки.
5. Для каждой фотографии последовательно вызвать её через `await asyncio.to_thread(...)` и создать `PhotoResponse`.
6. Создать и вернуть `AlbumDetailResponse`.

Проверка существования предшествует проверке владельца. Для отсутствующего и чужого альбома операции формирования ссылок не вызываются. При ошибке формирования одной из ссылок частичный ответ не возвращается.

### Результат

`AlbumDetailResponse` содержит:

| Поле | Содержание |
|---|---|
| `id`, `title` | Идентификатор и название альбома |
| `situation` | Ситуация, для которой создавался альбом |
| `styles`, `shoes`, `impressions` | Сохранённые параметры образов |
| `created_at`, `is_archived` | Дата создания и признак архивирования |
| `total_photos` | Значение из записи альбома |
| `photos` | Список объектов с полями `id`, `order_index`, `url` |

Сервис сохраняет порядок входного `album.photos`. В рабочей ORM-модели порядок задан через `Photo.order_index`; дополнительной сортировки в сервисе нет.

Пустая коллекция фотографий допустима и даёт `photos=[]`. Сервис не пересчитывает `total_photos` и не проверяет его равенство длине коллекции. Правило генерации пяти фотографий относится к сценарию генерации: этот метод возвращает имеющиеся данные и не ограничивает их количество пятью или десятью.

Архивный альбом не отклоняется только из-за `is_archived`. Метод также не требует статуса `COMPLETED` для получения по идентификатору.

### Ошибки

| Условие | Результат |
|---|---|
| Альбом отсутствует | `HTTPException(404, "Album not found or deleted.")` |
| Альбом принадлежит другому пользователю | `HTTPException(403, "Access to this album is forbidden.")` |
| Ошибка БД или формирования ссылки | Исключение зависимости распространяется вызывающему коду; отдельное преобразование и повтор в этом методе отсутствуют |
| Данные не соответствуют схемам ответа | Возможна ошибка валидации Pydantic |

Название сообщения 404 не означает наличие проверки признака удаления: фактически условие — отсутствие результата репозитория.

HTTP 401 при неверном JWT и HTTP 422 при неверном формате UUID относятся к обработчику API и его зависимостям, а не к логике `AlbumService`.

### Владение и побочные эффекты

Метод не изменяет полученные ORM-объекты. Результат состоит из новых DTO и не требует сохранения открытой сессии БД для чтения фотографий ответа. Это не обещание глубокого копирования любых возможных пользовательских объектов.

Побочные эффекты — чтение через репозиторий, выполнение операций хранилища и использование пула потоков. Формирование ссылки в рабочем `StorageService` может обращаться к MinIO для определения региона. Поэтому операцию нельзя считать полностью чистой или гарантированно не использующей сеть.

Подписанная ссылка действует ограниченное время, определяемое `MINIO_PRESIGNED_TTL`. Её формирование не доказывает существование объекта или доступность адреса из браузера. Уже выданная ссылка не требует JWT приложения до истечения её срока действия.

## Получение списка идентификаторов альбомов

```python
async def get_user_album_ids(
    self,
    user_id: uuid.UUID,
) -> UserAlbumIdsResponse:
    ...
```

Метод вызывает `album_repo.get_user_album_ids(user_id)` и возвращает:

- `album_ids` — полученный список UUID;
- `total` — `len(album_ids)`.

Пустой результат допустим: `album_ids=[]`, `total=0`. Хранилище не используется. Исключения репозитория не перехватываются.

В рабочем репозитории по умолчанию выбираются альбомы указанного пользователя со статусом `COMPLETED`, в порядке даты создания от новых к старым. Это правило реализовано репозиторием; сам сервис не выполняет повторную фильтрацию. Дополнительного исключения архивных альбомов в указанном запросе нет.

Аутентификация и выбор правильного `user_id` — обязанность потребителя. Сервис самостоятельно не устанавливает личность пользователя.

## Пример использования

Пример предполагает уже подготовленные зависимости и проверенные идентификаторы:

```python
from app.services.album_service import AlbumService

service = AlbumService(album_repo=album_repo, storage=storage)

detail = await service.get_album(album_id, current_user.id)
own_albums = await service.get_user_album_ids(current_user.id)
```

Это фрагмент асинхронного сценария, а не самостоятельный скрипт запуска.

## Подмена зависимостей и проверки

В `tests/test_albums.py` существуют `InMemoryAlbumRepository` и `InMemoryStorageService`. Они передаются через тот же конструктор, позволяя проверить сервис без PostgreSQL и MinIO.

При подмене репозиторий должен сохранять смысл результата, фильтрацию и порядок, на которые рассчитывает потребитель. Поставщик ссылок должен возвращать строку для переданного ключа. Одинаковых сигнатур недостаточно для взаимозаменяемости.

Текущие аннотации конструктора ссылаются на конкретные классы, а не отдельные `Protocol`. Это существующее ограничение границы, а не реализованная независимость от инфраструктурных типов.

Проверяемые случаи:

- собственный альбом: поля ответа и ссылки соответствуют фотографиям;
- пустая коллекция: ответ допустим, формирование ссылок не вызывается;
- отсутствующий альбом: 404;
- чужой альбом: 403 без формирования ссылок;
- список альбомов: только данные переданного пользователя, корректное `total`;
- на HTTP-границе: отсутствие токена, неверный UUID, структура ответа.

Существующий набор запускается из `src/backend_core` в подготовленном окружении:

```bash
python -m pytest tests/test_albums.py -v
```

Тесты с подменами не подтверждают работоспособность реальной БД, S3-сервера, корректность DNS, фактическое открытие ссылок или полный путь генерации. Эти свойства требуют отдельной интеграционной проверки.
