# Договор главного оркестратора

## Внутренние операции для службы API

| Операция | Вход | Результат |
| --- | --- | --- |
| `create_job` | Проверенный запрос и хеш ключа повтора | `job_id`, состояние и количество |
| `get_job` | `job_id` | Сохранённое состояние и готовые результаты |
| `cancel_job` | `job_id` | Новое или уже конечное состояние |

Внутренний вызов доступен только службе API и защищён служебной идентификацией.
Повтор каждой операции безопасен.

## Договор с групповыми оркестраторами

Главный оркестратор публикует только сообщения уровня `ai.stage.*` и получает
только результаты уровня `ai.stage.*`, описанные в
[общем договоре](../../message-contracts.md). Сообщения `ai.worker.*` ему
недоступны.
Для каждого этапа он обязан:

1. сохранить новый `stage_run_id`, `lease_token` и команду в `ai_outbox` одной операцией;
2. принять результат только с текущими `job_id`, `result_index`, `stage_run_id` и
   `lease_token`;
3. сохранить `message_id` результата в `ai_inbox`;
4. записать новый этап до публикации следующей команды.

## Конечные состояния

`COMPLETED`, `FAILED` и `CANCELLED` необратимы. `COMPLETED` допустим только при
наличии ровно `requested_image_count` принятых результатов. Позднее или повторное
сообщение не может изменить конечное состояние.
