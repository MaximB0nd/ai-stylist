# Архитектура генерации образов AI Stylist

## 1. Цель

Система должна создавать реалистичную фотографию человека в полный рост в новом, подходящем ему комплекте одежды.

На вход поступают:

1. фотография лица человека;
2. фотография человека в полный рост;
3. текстовое описание желаемого результата;
4. известные данные о человеке: рост, пол и другие параметры;
5. количество итоговых изображений `N`.

На выходе система возвращает ссылки на `N` сохранённых фотографий человека в полный рост в разных подобранных комплектах одежды.

В рамках одной итерации создания `N` фотографий комплекты не должны повторяться. Для этого AI Core ведёт временный список уже выбранных образов и очищает его после завершения итерации.

## 2. Основная идея

Процесс разделяется на две независимые логические части:

1. **AI-стилист** определяет, во что одеть человека, и формирует структурированное описание комплекта.
2. **AI-фотограф** визуализирует выбранный комплект в случайной стоячей позе, сохраняя внешность человека и его телосложение.

### 2.1. Минимальная схема системы

![Архитектура AI-системы](./images/ai-system-architecture.png)

- Основной backend показан только как внешний клиент независимого AI Backend.
- AI Backend владеет очередью, оркестрацией, повторными попытками и временным состоянием текущей итерации.
- AI Backend не обращается к базе данных или файловому хранилищу напрямую. Для сохранения готовых изображений он вызывает внешний модуль хранения, не зная его внутренней реализации.
- AI Backend возвращает основному backend статус и ссылки на сохранённые изображения.
- Model-server'ы доступны AI Backend: стилист и фотограф могут работать на одной GPU или на неделимой группе из нескольких GPU; пропускная способность масштабируется независимыми репликами таких групп.

## 3. Общий процесс обработки

```text
Frontend
   │
   ▼
Основной Backend
   │
   ├── авторизация и продуктовая логика
   └── вызов независимого AI Backend через AI Request API
           │
           ▼
AI Backend
   ├── создание AI-задания
   ├── управление очередью
   └── возврат статуса и результата
           │
           ▼
1. Подготовка фотографий
           │
           ▼
2. Подбор нескольких комплектов
           │
           ▼
3. Проверка комплектов на повторение
           │
           ▼
4. Выбор OutfitSpec
           │
           ▼
5. Генерация фотографии
           │
           ▼
6. Автоматическая проверка результата
           │
           ▼
7. Сохранение изображений через внешний модуль хранения
           │
           ▼
8. Возврат ссылок основному Backend
```

## 4. Подбор одежды

AI-стилист получает:

- профиль человека;
- классы предыдущего этапа;
- временный список комплектов, уже созданных в текущей итерации;
- контекст мероприятия, сезона, погоды.

Стилист формирует несколько кандидатов в виде `OutfitSpec`, после чего система выбирает подходящий вариант, отсутствующий во временном списке текущей итерации. После успешной генерации выбранный комплект добавляется в список. Когда все `N` изображений готовы или итерация завершилась ошибкой, список очищается.

## 5. Генерация изображения

В модель передаются:

- лицо как референс идентичности;
- исходная фотография в полный рост как источник телосложения и пропорций;
- структурированное описание нового комплекта от AI-стилиста;
- инструкция сохранить лицо и телосложение, изменить одежду и использовать случайную стоячую позу.

```text
Фото лица ───────────────┐
                         │
Фото в полный рост ──────┤─► image editing ──► результат
                         │
OutfitSpec ──────────────┘
```

## 6. Компоненты системы

```text
Основной Backend
   │
   ▼
API AI Core
   └── Очередь AI-заданий
          └── AI-оркестратор
                 ├── Подготовка изображений
                 ├── Подбор комплектов
                 ├── Проверка новизны внутри итерации
                 ├── Генерация изображений
                 ├── Проверка результата
                 └── Сохранение через внешний модуль хранения
```

| Компонент | Ответственность |
| --- | --- |
| API AI Core | Единственная внешняя точка входа и управление AI-заданиями |
| Очередь AI-заданий | Асинхронное выполнение, повторные попытки и временное состояние итерации |
| AI-оркестратор | Последовательность этапов и передача данных между ними |
| AI-стилист | Формирование и проверка описания комплекта `OutfitSpec` |
| AI-фотограф | Создание итогового изображения |
| Проверка результата | Контроль сходства, полного роста, одежды и качества изображения |
| Внешний модуль хранения | Постоянное сохранение готового изображения и возврат ссылки |

Основной backend общается только с API независимого AI Core. Внутренние очередь, оркестратор и серверы моделей не раскрываются внешним потребителям. AI Core не знает, какая база данных или файловое хранилище используется внешним модулем хранения.

## 7. Состояние итерации и хранение результата

Один запрос на создание `N` фотографий образует одну итерацию. Пока она выполняется, AI Core временно хранит:

- идентификатор задания и количество требуемых изображений;
- уже выбранные `OutfitSpec` или их признаки для проверки повторов;
- состояние каждого создаваемого изображения и количество попыток;
- ссылки, полученные от внешнего модуля хранения.

Временный список используется только для исключения повторяющихся образов внутри этой итерации. После успешного завершения или окончательной ошибки он очищается и не используется в следующих запросах.

Проверенное итоговое изображение AI Core передаёт внешнему модулю хранения. Модуль сохраняет файл и возвращает ссылку, которую AI Core передаёт основному backend. Версия модели, параметры генерации и начальное значение генератора случайных чисел `seed` должны передаваться вместе с результатом для воспроизводимости и расследования ошибок.
