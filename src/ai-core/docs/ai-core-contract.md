# Договор взаимодействия с AI Core

## 1. Назначение

Документ определяет внешний договор между основным сервером и AI Core. Общая
архитектура описана отдельно в
[image-generation-architecture.md](image-generation-architecture.md).

Все операции выполняются во внутренней сети. Основной сервер передаёт служебный
токен в заголовке `Authorization: Bearer <service-token>`. Токен задаётся в
настройках AI Core, не записывается в репозиторий и не попадает в журналы. Тела
запросов не содержат идентификатор пользователя.

## 2. Защита от повторного создания

Основной сервер создаёт непрозрачный уникальный ключ запроса и передаёт его только
в заголовке `Idempotency-Key`. Это может быть его идентификатор генерации или
отдельное случайное значение: AI Core не различает эти варианты и не возвращает
ключ в ответах и уведомлениях.

Если основной сервер повторит запрос с тем же ключом, AI Core вернёт ранее
созданное задание. Новое задание и повторная генерация не создаются.

## 3. Создание задания

```text
POST /v1/jobs
Idempotency-Key: <непрозрачный уникальный ключ>
```

```json
{
  "requested_image_count": 7,
  "inputs": {
    "face_photo_url": "https://storage.example/internal/temporary-face-url",
    "body_photo_url": "https://storage.example/internal/temporary-body-url",
    "expires_at": "2026-09-26T21:00:00Z"
  },
  "person": {
    "age": 26,
    "height_cm": 172,
    "gender": "female"
  },
  "preferences": {
    "occasion": "office",
    "styles": ["classic", "minimalism"],
    "shoes": ["loafers"],
    "impressions": ["confident", "elegant"],
    "description": "Сдержанные образы для офиса"
  }
}
```

AI Core проверяет количество изображений по собственным настройкам. Ссылки на
исходники должны жить не меньше срока `AI_CORE_INPUT_URL_MIN_TTL_SECONDS`. На
этапе подготовки AI Core копирует исходники во временную закрытую область и не
зависит от этих ссылок во время последующей очереди.

Успешный ответ:

```json
{
  "job_id": "c84dfb50-f331-4c12-88f5-3c1a3e6015aa",
  "status": "QUEUED",
  "requested_image_count": 7,
  "status_url": "/v1/jobs/c84dfb50-f331-4c12-88f5-3c1a3e6015aa"
}
```

## 4. Получение состояния

```text
GET /v1/jobs/{job_id}
```

```json
{
  "job_id": "c84dfb50-f331-4c12-88f5-3c1a3e6015aa",
  "status": "GENERATING",
  "requested_image_count": 7,
  "accepted_image_count": 3,
  "failed_attempt_count": 1,
  "updated_at": "2026-09-26T19:30:00Z",
  "error": null
}
```

Основные состояния:

- `QUEUED` — ожидает выполнения;
- `PREPARING` — копируются и проверяются исходники;
- `STYLING` — подбирается комплект;
- `GENERATING` — создаётся изображение;
- `VERIFYING` — проверяется результат;
- `SAVING` — сохраняются принятые результаты;
- `COMPLETED` — сохранено ровно запрошенное количество результатов;
- `FAILED` — лимит допустимых попыток исчерпан или возникла окончательная ошибка;
- `CANCELLED` — задание отменено.

## 5. Уведомление о смене состояния

AI Core отправляет уведомление на адрес из своей настройки
`AI_CORE_STATUS_CALLBACK_URL` при каждой значимой смене состояния. Пользователь
не может передать или изменить этот адрес через запрос создания задания.

Уведомление содержит заголовки `X-AI-Core-Timestamp` и
`X-AI-Core-Signature`. Подпись вычисляется через HMAC-SHA256 от времени и исходного
тела запроса с секретом `AI_CORE_STATUS_CALLBACK_SECRET`. Основной сервер проверяет
подпись, допустимый возраст сообщения и уникальность `event_id`.

```json
{
  "event_id": "4964143c-b10a-4d89-80b5-5cf9d488d8e2",
  "job_id": "c84dfb50-f331-4c12-88f5-3c1a3e6015aa",
  "sequence": 5,
  "status": "GENERATING",
  "progress": {
    "requested_image_count": 7,
    "accepted_image_count": 3
  },
  "occurred_at": "2026-09-26T19:30:00Z",
  "error": null
}
```

Правила доставки:

- AI Core сохраняет событие до подтверждения основным сервером;
- ответ с кодом `2xx` подтверждает получение;
- при временной ошибке AI Core повторяет доставку;
- `event_id` защищает основной сервер от повторной обработки;
- `sequence` только растёт и позволяет не применять старое состояние поверх нового;
- уведомление сообщает об изменении, но текущее состояние всегда можно проверить
  запросом `GET /v1/jobs/{job_id}`.

## 6. Завершённое задание

Для `COMPLETED` ответ состояния и уведомление содержат результаты:

```json
{
  "job_id": "c84dfb50-f331-4c12-88f5-3c1a3e6015aa",
  "status": "COMPLETED",
  "requested_image_count": 2,
  "accepted_image_count": 2,
  "results": [
    {
      "order_index": 0,
      "object_key": "generations/job-id/results/look-00.webp",
      "checksum_sha256": "<sha256>",
      "width": 1024,
      "height": 1536,
      "model_version": "<model-version>",
      "prompt_version": "<prompt-version>",
      "outfit_spec_version": "1.0",
      "seed": 12345
    },
    {
      "order_index": 1,
      "object_key": "generations/job-id/results/look-01.webp",
      "checksum_sha256": "<sha256>",
      "width": 1024,
      "height": 1536,
      "model_version": "<model-version>",
      "prompt_version": "<prompt-version>",
      "outfit_spec_version": "1.0",
      "seed": 67890
    }
  ],
  "error": null
}
```

Количество элементов `results` при `COMPLETED` всегда равно
`requested_image_count`. Постоянное владение объектами, создание альбома и
последующее удаление результатов относятся к основному серверу.

Если лимит попыток исчерпан до получения полного количества, задание переходит в
`FAILED`. Уже созданные изображения не объявляются успешным частичным результатом.

## 7. Отмена

```text
POST /v1/jobs/{job_id}/cancel
```

Отмена запрещает выдачу новых попыток, сообщает активному исполнителю о
необходимости остановки и переводит задание в `CANCELLED`. Поздний результат
отменённой попытки не может вернуть задание в работу. AI Core удаляет свои
временные данные; постоянные файлы удаляет основной сервер.

## 8. Ошибки и повторные попытки

Ошибки делятся на две группы:

- временные: недоступность модели, нехватка памяти, задержка сети или хранилища;
- окончательные: неверный запрос, запрещённое содержимое, недоступные исходники
  после установленного срока, отмена задания.

Временные ошибки повторяются в пределах настроек AI Core. Окончательная ошибка
переводит задание в `FAILED` и содержит безопасный код ошибки без пользовательских
данных и внутренних следов выполнения.
