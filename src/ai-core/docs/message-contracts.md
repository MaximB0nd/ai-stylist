# Внутренние сообщения AI Core

## 1. Два уровня очередей

В AI Core два уровня управления:

1. главный оркестратор отправляет этап целиком оркестратору нужной группы;
2. групповой оркестратор делит этап на попытки и раздаёт их своим воркерам.

Воркеры не вызывают друг друга и не общаются с главным оркестратором напрямую.
RabbitMQ отвечает за доставку, а постоянное состояние хранится в базах
оркестраторов.

## 2. Очереди между главным и групповыми оркестраторами

| Группа | Команды группе | Результаты группы |
| --- | --- | --- |
| Подготовка фотографий | `ai.stage.photo.prepare.commands` | `ai.stage.photo.prepare.results` |
| Подбор комплекта | `ai.stage.outfit.style.commands` | `ai.stage.outfit.style.results` |
| Генерация изображения | `ai.stage.image.generate.commands` | `ai.stage.image.generate.results` |
| Проверка результата | `ai.stage.image.verify.commands` | `ai.stage.image.verify.results` |
| Очистка временных данных | `ai.stage.temporary.cleanup.commands` | `ai.stage.temporary.cleanup.results` |
| Доставка уведомлений | `ai.stage.status.notify.commands` | `ai.stage.status.notify.results` |

## 3. Очереди внутри групп

| Группа | Команды воркерам | Результаты воркеров |
| --- | --- | --- |
| Подготовка фотографий | `ai.worker.photo.prepare.commands` | `ai.worker.photo.prepare.results` |
| Подбор комплекта | `ai.worker.outfit.style.commands` | `ai.worker.outfit.style.results` |
| Генерация изображения | `ai.worker.image.generate.commands` | `ai.worker.image.generate.results` |
| Проверка результата | `ai.worker.image.verify.commands` | `ai.worker.image.verify.results` |
| Очистка временных данных | `ai.worker.temporary.cleanup.commands` | `ai.worker.temporary.cleanup.results` |
| Доставка уведомлений | `ai.worker.status.notify.commands` | `ai.worker.status.notify.results` |

Для каждой очереди команд создаётся отдельная очередь окончательно не
обработанных сообщений. Группы разделяются правами RabbitMQ: служба одной группы
не может читать очередь другой.

## 4. Общая оболочка сообщения

```json
{
  "message_id": "67b6fd73-9699-4e50-8cc0-7fd1865ed46a",
  "message_type": "worker.image.generate.command",
  "schema_version": "1.0",
  "job_id": "c84dfb50-f331-4c12-88f5-3c1a3e6015aa",
  "stage_run_id": "c9f5ad1d-b484-457f-829b-fd90d6f58ac8",
  "result_index": 3,
  "attempt": 2,
  "lease_token": 17,
  "correlation_id": "56912f8e-846e-409a-b894-d7f7b5834607",
  "created_at": "2026-09-27T00:10:00Z",
  "payload": {}
}
```

- `message_id` защищает от повторной обработки сообщения;
- `job_id` связывает все группы одного задания;
- `stage_run_id` обозначает конкретный запуск этапа;
- `result_index` обозначает место результата от `0` до `N - 1`;
- `attempt` обозначает попытку внутри группы;
- `lease_token` защищает от устаревшего результата;
- `correlation_id` связывает команду и ответ;
- `schema_version` определяет формат `payload`.

## 5. Кто принимает решения

Главный оркестратор решает:

- какой этап конвейера запускать;
- сколько результатов ещё требуется;
- когда задание завершено, отменено или окончательно провалено;
- какой комплект зарезервирован для конкретного результата.

Групповой оркестратор решает:

- какой копии воркера отдать попытку;
- повторить ли временную техническую ошибку;
- истёк ли срок конкретной попытки;
- какой итог этапа вернуть главному оркестратору.

Воркер только выполняет одну команду и возвращает результат. Он не назначает
повторы и не меняет состояние задания.

## 6. Доставка и подтверждение

- Используются постоянные очереди и сохраняемые сообщения.
- Издатель ждёт подтверждение RabbitMQ.
- Получатель подтверждает входное сообщение только после сохранения своего
  состояния и исходящего результата.
- RabbitMQ может доставить любое сообщение повторно.
- Каждый оркестратор хранит уже обработанные `message_id`.
- Повтор команды не должен создавать второй объект или второй переход состояния.
- После превышения технических повторов сообщение попадает в очередь ошибок.

## 7. Повторы и сроки

Повтор доставки того же сообщения не увеличивает номер попытки. Новую попытку с
новым `attempt` и `lease_token` создаёт групповой оркестратор. Главный оркестратор
видит один итог запуска группы и не управляет отдельными воркерами.

Если групповой оркестратор не вернул итог за установленное время, главный
оркестратор может отменить текущий `stage_run_id` и создать новый. Поздний ответ
старого запуска не принимается.

## 8. Масштабирование

Для каждой группы независимо меняются число копий группового оркестратора и число
воркеров. Обычно оркестратор требует мало ресурсов, а воркеры масштабируются по
глубине своей очереди и доступному оборудованию.

Если генераторы не успевают, растут только очереди группы генерации. Главный
оркестратор ограничивает число одновременно открытых этапов, а групповой — число
одновременно работающих попыток.

## 9. Совместимость

Добавление необязательного поля не меняет старшую версию. Удаление поля, изменение
его типа или смысла создаёт новую старшую версию. Во время обновления отправитель
и получатель временно поддерживают текущую и предыдущую версии.
