# Последовательность разработки AI Core

## 1. Документы и договоры

- зафиксировать общую архитектуру отдельно от внешнего договора;
- зафиксировать форматы создания, чтения и отмены задания;
- зафиксировать формат исходящих уведомлений о состоянии;
- описать состояния, постоянную очередь и восстановление после сбоя;
- описать `OutfitSpec` версии 1 и таксономию одежды;
- описать настройки AI Core и допустимый диапазон количества изображений;
- подготовить план проверки моделей.

Документы AI Core являются исходным договором для интеграции. Основной сервер
подстраивает свою реализацию под опубликованную версию договора.

## 2. Проверка моделей

- собрать закрытый набор с согласием участников;
- подготовить обезличенное описание набора;
- реализовать воспроизводимый запуск проверки;
- провести быструю проверку процесса;
- сравнить модели на полном наборе;
- выбрать модель и минимальное оборудование по записанным заранее показателям.

## 3. Последовательный прототип

- реализовать формирование и проверку `OutfitSpec`;
- последовательно создавать одно изображение за раз;
- сохранять версии модели, инструкции, `OutfitSpec` и `seed`;
- подключить базовую проверку качества и безопасности;
- подтвердить достижимость требуемого количества результатов.

Прототип не содержит постоянную очередь и не считается готовой серверной версией.

## 4. Первая серверная версия

- реализовать внешний программный интерфейс AI Core;
- добавить собственную PostgreSQL и постоянную очередь;
- добавить аренду задания, продление аренды и восстановление после сбоя;
- хранить состояние каждого места результата и историю попыток;
- добавить атомарное резервирование комплектов;
- подключить временный доступ к модулю хранения;
- отправлять основному серверу сохранённые уведомления о смене состояния;
- реализовать отмену и очистку временных данных;
- добавить журналы, показатели и предупреждения для очереди, моделей и очистки.

## 5. Повышение качества

- улучшать сохранение лица и телосложения по результатам полной проверки;
- добавить автоматический выбор лучшего результата;
- учитывать пользовательские оценки без смешивания с закрытым набором;
- расширить набор поз и фонов;
- повторять полный прогон перед сменой основной модели.

## 6. Масштабирование

- измерить длину очереди, время ожидания и загрузку оборудования;
- добавлять исполнителей независимо от внешнего программного интерфейса;
- выносить модели в отдельные службы только при доказанной конкуренции за память
  или разных требованиях к масштабированию;
- добавлять отдельный брокер сообщений только если очередь PostgreSQL не выполняет
  измеренные требования;
- добавлять распределённый запуск после проверки на целевом оборудовании.

## 7. Расширение сценариев

- поддержать фотографии конкретных предметов одежды;
- при необходимости добавить специализированную виртуальную примерку;
- интегрировать каталог реально доступной одежды.
