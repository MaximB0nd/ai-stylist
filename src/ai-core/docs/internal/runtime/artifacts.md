# Временные файлы

## Ответственность

| Объект | Владелец |
| --- | --- |
| Временное хранилище и его ключи | Служба временных файлов |
| Сведения о файлах задания | Главный оркестратор |
| Постоянное хранение результатов | Основной сервер |

- Только служба временных файлов обращается к временному S3.
- Processing services и основной сервер работают через короткие ссылки только
  к службе временных файлов; произвольные внешние URL не допускаются.
- AI Core не обращается к постоянному хранилищу продукта.
- Байты файлов не проходят через главный оркестратор или транспортный адаптер.

## Жизненный цикл

1. Главный оркестратор создаёт идентификатор временного файла.
2. Служба временных файлов выдаёт ссылку на чтение или запись.
3. Processing service читает или записывает файл по ссылке.
4. Основной сервер скачивает принятый результат.
5. После подтверждения, ошибки, отмены или окончания срока файл удаляется.

При записи служба временных файлов сначала сохраняет поток в непубличный ключ,
проверяет формат и ресурсные пределы и только затем делает объект доступным для
чтения. Она не меняет пиксели и не выполняет предметную ML-проверку.

Повторное удаление безопасно. Точный формат идентификаторов, ссылок и сроки
определяются при реализации службы.
