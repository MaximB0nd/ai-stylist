# Временные файлы

## Ответственность

| Объект | Владелец |
| --- | --- |
| Временное хранилище и его ключи | Служба временных файлов |
| Сведения о файлах задания | Главный оркестратор |
| Постоянное хранение результатов | Основной сервер |

- Только служба временных файлов обращается к временному S3.
- Processing services и основной сервер работают через короткие ссылки только
  к службе временных файлов; произвольные внешние URL не допускаются.
- Единственное исключение — управляемый оркестратором импорт исходных фотографий
  с настроенного HTTPS-origin основного сервера.
- AI Core не обращается к постоянному хранилищу продукта.
- Байты файлов не проходят через главный оркестратор или транспортный адаптер.

## Жизненный цикл

1. Главный оркестратор создаёт отдельный `artifact_id` для каждого входа.
2. Служба временных файлов по команде оркестратора потоково импортирует вход с
   разрешённого origin, проверяет его и публикует во временном S3.
3. Для промежуточного или выходного файла оркестратор заранее создаёт новый
   `artifact_id`.
4. Служба временных файлов выдаёт короткую ссылку на чтение или запись.
5. Processing service читает файл через `GET` или записывает сырое тело через
   `PUT` по выданной ссылке.
6. Основной сервер скачивает принятый результат.
7. После подтверждения, ошибки, отмены или окончания срока файл удаляется.

При записи служба временных файлов сначала сохраняет поток в непубличный ключ,
проверяет формат и ресурсные пределы и только затем делает объект доступным для
чтения. Она не меняет пиксели и не выполняет предметную ML-проверку.

Повтор завершённого импорта и повторное удаление безопасны. Точный формат
идентификаторов, ссылок и сроки определяются при реализации службы.
