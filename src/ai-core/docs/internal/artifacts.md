# Временные файлы

## Владение

| Объект | Владелец |
| --- | --- |
| Временное S3 | AI Core |
| Ключи временного S3 | Служба временных файлов |
| Метаданные файла | Главный оркестратор |
| Постоянные файлы | Основной сервер |

AI Core не имеет доступа к постоянному хранилищу продукта.

## Идентификатор

`artifact_id` создаёт главный оркестратор до записи файла.

Уникальное место файла:

```text
job_id + worker_run_id + purpose + slot
```

Повтор для того же места возвращает тот же `artifact_id`.

## Доступ

- Служба временных файлов выдаёт короткую ссылку на одну операцию: `READ` или `WRITE`.
- Ссылка ведёт на службу временных файлов.
- Служба передаёт данные между клиентом ссылки и S3 потоком.
- Воркеры и основной сервер не получают адрес и ключи S3.
- Результат воркера содержит `artifact_id`, SHA-256, размер, формат, ширину и высоту.
- Ссылки не хранятся в базе, сообщениях об ошибках и журналах.

## Передача результата

1. AI Core возвращает `artifact_id`, ссылку, срок, SHA-256, размер и формат.
2. Основной сервер скачивает файл и проверяет SHA-256.
3. Основной сервер сохраняет файл постоянно.
4. Основной сервер вызывает `POST /v1/jobs/{job_id}/results/ack`.

## Удаление

| Причина | Действие |
| --- | --- |
| Получен ACK | Команда очистки по `artifact_id` |
| Ошибка или отмена | Команда очистки известных файлов |
| ACK не получен | Удаление по предельному сроку |

- Повторное удаление безопасно.
- После закрытия или истечения срока новые ссылки не выдаются.
- Поздняя попытка не восстанавливает удалённый объект.
- Предельный срок: [configuration.md](configuration.md#служба-временных-файлов).
