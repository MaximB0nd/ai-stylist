# Общий договор processing services

## Область действия

Этот договор обязателен для независимо разворачиваемых служб обработки AI Core:
проверок, нормализации, классификации, стилизации и генерации. Главный
оркестратор, внешний API и служба временных файлов имеют собственные договоры.

Служба обработки решает одну задачу и не зависит от конкретного процесса,
оркестратора или транспорта между системами. Её можно вызвать из AI Core,
другого продукта, локального инструмента или отдельного транспортного адаптера.

## Граница ответственности

Служба обработки:

- предоставляет синхронный внутренний HTTP API на FastAPI;
- загружает и запускает только принадлежащие ей модели;
- читает входные файлы по переданным коротким ссылкам;
- при наличии файлового результата записывает его по переданной ссылке;
- возвращает решение или метаданные результата;
- остаётся stateless и не имеет базы состояния заданий;
- не вызывает другие processing services;
- не выбирает следующий этап, не планирует повтор и не меняет состояние задания;
- ничего не знает о RabbitMQ, другой очереди или формате сообщения в ней.

Порядок вызовов, параллельность, таймауты, повторы и сохранение состояния
принадлежат вызывающей стороне. Если позже появится очередь, отдельный
транспортный адаптер преобразует сообщение в HTTP-вызов службы и обратно.

## Транспорт

| Правило | Значение |
| --- | --- |
| Сеть | внутренняя, HTTPS |
| Формат метаданных | `application/json` |
| Авторизация | `Authorization: Bearer <service-token>` |
| Корреляция | `request_id`, UUID |
| Файлы | короткие `read_url` и `write_url`, не байты в JSON |
| Состояние задания | не передаётся |

`request_id` связывает журналы и ответ с вызовом, но не несёт смысла задания.
Служба возвращает его без изменения. Ссылки, токены и содержимое изображений
запрещено журналировать.

Пример входного файла:

```json
{
  "request_id": "4bb167f7-cfeb-4c4c-b4ba-c63e64e96adb",
  "image": {
    "read_url": "https://temporary-files.example/opaque-read-token",
    "checksum_sha256": "sha256:example"
  }
}
```

Для файлового результата вызывающая сторона заранее передаёт `write_url`.
Служба не получает адрес S3 или ключи доступа и не сохраняет файл локально
дольше одного вызова.

## Решения и ошибки

Ожидаемое отрицательное решение модели является успешным HTTP-вызовом:

```json
{
  "request_id": "4bb167f7-cfeb-4c4c-b4ba-c63e64e96adb",
  "decision": "REJECTED",
  "reasons": ["FACE_TOO_BLURRY"],
  "model_version": "model@revision"
}
```

Транспортные и контрактные ошибки имеют единый вид:

```json
{
  "error": {
    "code": "INPUT_UNAVAILABLE",
    "message": "Входной файл временно недоступен",
    "retryable": true
  }
}
```

| HTTP | Условие |
| ---: | --- |
| `400` | неверная структура или параметры запроса |
| `401` | неверный служебный токен |
| `409` | конфликт ожидаемого и фактического checksum или состояния записи |
| `415` | неподдерживаемый тип файла |
| `422` | файл нельзя прочитать или обработать по договору службы |
| `429` | локальный предел параллельных вызовов |
| `503` | модель или обязательная зависимость не готовы |

Только вызывающая сторона решает, повторять ли ошибку с `retryable: true`.

## Повтор вызова

- Служба не хранит историю `request_id` и не подавляет дубликаты через БД.
- Повтор детерминированной операции с теми же входами и настройками должен быть
  безопасен.
- Для недетерминированной модели вызывающая сторона передаёт фиксированный
  `seed`, если повтор должен воспроизвести результат.
- Повтор записи использует тот же логический выход и может заменить только его.
- За запрет одновременных и устаревших вызовов отвечает вызывающая сторона.

## Модель

- Репозиторий Hugging Face и точная revision задаются настройками.
- Модель загружается один раз при старте процесса.
- Успешный модельный ответ содержит `model_version` в виде `model@revision`.
- Смена модели или порога не меняет HTTP-договор без изменения формы ответа.
- Готовность становится успешной только после загрузки модели и проверки
  обязательных зависимостей.

## Служебные endpoints

```text
GET /health/live
GET /health/ready
```

- `live` подтверждает работу процесса.
- `ready` подтверждает загрузку модели и готовность принимать вызовы.
- Endpoint готовности не запускает inference и не раскрывает секреты.

## Наблюдаемость и данные

- Журнал содержит службу, `request_id`, endpoint, безопасный код результата и
  длительность.
- Метрики содержат число вызовов, решения, ошибки, время inference, RAM и VRAM.
- Изображения, ссылки, токены, embedding личности и извлечённые признаки кожи
  не журналируются.
- После ответа временные буферы и локальные файлы вызова удаляются.
