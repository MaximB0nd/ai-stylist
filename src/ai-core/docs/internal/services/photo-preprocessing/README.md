# Группа предобработки фотографий

## Для чего создана

Группа содержит независимые processing services, которые проверяют две входные
фотографии, подтверждают личность, нормализуют изображения и определяют один из
четырёх цветотипов. Группа — только навигационная граница документации и не
является отдельной службой или оркестратором.

## Службы

| Служба | Ответственность | Договор |
| --- | --- | --- |
| [Проверка лица](face-validation/README.md) | пригодность фотографии лица | [HTTP](face-validation/CONTRACT.md) |
| [Проверка полного роста](body-validation/README.md) | пригодность фотографии человека в полный рост | [HTTP](body-validation/CONTRACT.md) |
| [Проверка личности](identity-verification/README.md) | один ли человек на двух фотографиях | [HTTP](identity-verification/CONTRACT.md) |
| [Нормализация человека](person-normalization/README.md) | удаление фона и нормализация одного изображения | [HTTP](person-normalization/CONTRACT.md) |
| [Определение цветотипа](color-type/README.md) | один из четырёх сезонных цветотипов | [HTTP](color-type/CONTRACT.md) |

Все службы следуют [общему HTTP-договору](../CONTRACT.md), независимо
разворачиваются и не знают о порядке полного процесса.

## Семантика результатов

| Служба | HTTP `200` | HTTP `422` |
| --- | --- | --- |
| Проверка лица | `ACCEPTED` или `REJECTED` | изображение технически нельзя обработать |
| Проверка полного роста | `ACCEPTED` или `REJECTED` | изображение технически нельзя обработать |
| Проверка личности | `SAME_PERSON` или `DIFFERENT_PERSON` | сравнение невозможно по содержимому входа |
| Нормализация | записанный `artifact` | артефакт нельзя создать по содержимому входа |
| Определение цветотипа | один из четырёх `color_type` | надёжный цветотип нельзя вернуть |

У проверяющих служб отрицательное решение является полезным результатом самой
проверки. У остальных служб `200` допустим только при наличии обещанного
результата. Все ошибки возвращаются в формате Problem Details.

## Порядок в AI Core

```text
проверка лица ─┐
               ├→ проверка личности → нормализация лица ─┬→ цветотип
проверка тела ─┘                                         └→ нормализованное лицо
                       нормализация тела ──────────────────→ нормализованное тело
```

Проверки лица и полного роста можно вызвать параллельно. Identity service
самостоятельно находит и выравнивает лица собственным YuNet + SFace bundle и не
использует промежуточные данные validation services. После успешной проверки
личности normalizer получает только изображения, уже принятые соответствующей
проверкой; он не пересчитывает людей. Нормализация лица и полного роста может
выполняться параллельно. Цветотип определяется только по нормализованному лицу.

Color-type classifier оценивается на фактическом выходе normalizer. Если
начальный публичный кандидат не проходит закрытый benchmark, используется один
компактный классификатор, дообученный для контрактного RGB sRGB PNG, без
дополнительных inference-моделей для detection или skin masking.

Вход процесса не меняется: одна фотография лица и одна фотография в полный рост.
Успех содержит два нормализованных PNG на белом фоне и один цветотип:
`spring`, `summer`, `autumn` или `winter`.
