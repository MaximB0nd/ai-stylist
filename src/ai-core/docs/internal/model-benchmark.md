# Проверка моделей

## Цели

- проверить выполнение требований продукта;
- выбрать качество при допустимых времени и стоимости.

## Набор

| Требование | Значение |
| --- | --- |
| Участники | не менее 30, явное согласие |
| Фотографии | лицо и полный рост |
| Разнообразие | освещение, фон, телосложение |
| Ситуации | улица, учёба, офис, вечер |
| Задания | не менее 3 на ситуацию |
| Закрытая часть | не используется при настройке |
| Идентификаторы | непрозрачные, без прямых персональных данных |

Изображения не хранятся в Git.

## Запуски

| Запуск | Назначение | Объём |
| --- | --- | ---: |
| Быстрый | запуск, формат, грубые ошибки | 10 заданий |
| Полный | выбор моделей | весь закрытый набор |

Для полного запуска фиксируются версии моделей, образов, библиотек, настроек,
инструкций и `seed`. Неудачные попытки входят в статистику.

## Показатели

| Группа | Показатели |
| --- | --- |
| Качество | лицо, тело, полный рост, одежда, анатомия, материалы, повторы, безопасность |
| Надёжность | завершённые задания, попытки, ошибки, нехватка памяти, восстановление, повторы сообщений |
| Время | среднее на изображение, p50 и p95 задания, ожидание в очередях |
| Ресурсы | RAM, VRAM, изображения в час, стоимость изображения и задания |

Каждое изображение: два слепых оценщика; спор — третий оценщик.

## Отсечение кандидата

- запрещённое содержимое;
- изменение личности или телосложения;
- нет полного роста;
- повторяющиеся комплекты;
- не помещается на оборудование;
- не создаёт нужное число результатов в срок.

Пороговые значения фиксируются до полного запуска.

## Отчёт

- версия набора;
- модели, библиотеки, образы;
- оборудование и размещение;
- RabbitMQ и число копий воркеров;
- параметры генерации;
- версии `OutfitSpec` и инструкций;
- показатели и причины отклонений;
- ограничения и решение.

## Проверка распределённой системы

1. Параллельные задания с разным `requested_image_count`.
2. Изменение числа копий воркера.
3. Остановка воркеров и оркестратора.
4. Перезапуск RabbitMQ с командами.
5. Проверка потерь и дублей.
6. Определение ограничивающего этапа.

Успех: каждое задание завершено один раз, количество результатов совпало,
повторные сообщения не изменили итог.
