# Архитектура AI Core

## Результат

Ровно `requested_image_count` проверенных изображений без повторов комплектов.
До генерации AI Core проверяет две входные фотографии, нормализует их и
определяет один из четырёх цветотипов.

## Компоненты

| Компонент | Ответственность |
| --- | --- |
| Внешний интерфейс | HTTP-договор с основным сервером |
| Главный оркестратор | Состояние, порядок этапов, попытки, конечный результат |
| PostgreSQL | Состояние оркестратора |
| Служба временных файлов | Artifact gateway и единственный доступ к временному S3; безопасный поток, ссылки, удаление |
| Временное S3 | Входные копии, промежуточные файлы, результаты |
| Processing services | Одна переиспользуемая операция по синхронному HTTP |
| Основной сервер | Постоянное хранение и подтверждение получения |

Processing services следуют [общему договору](../services/CONTRACT.md). Они не
знают о полном процессе или транспортной инфраструктуре. Оркестратор вызывает
их по HTTP; очередь при необходимости подключается отдельным адаптером.

## Порядок этапов

```text
создание
  → проверка лица + проверка полного роста
  → проверка личности
  → нормализация лица + нормализация полного роста
  → цветотип
  → стилист
  → резерв комплекта
  → генерация
  → проверка
  → повтор или принятие
  → N результатов
  → скачивание
  → ACK
  → удаление файлов
```

Знак `+` означает этапы, которые оркестратор может запускать параллельно.

## Инварианты

- Один владелец каждого вида состояния.
- Один главный оркестратор; в первой версии — одна копия.
- Один PostgreSQL оркестратора.
- Processing services stateless, не имеют собственных баз состояния заданий и
  не вызывают друг друга.
- Каждая processing service разворачивается и масштабируется независимо.
- Каждый экземпляр processing service публикует live, ready и status; status
  сообщает локальную capacity, но не резервирует слот.
- При нескольких экземплярах конкретную реплику выбирает service discovery и
  внутренний балансировщик либо оркестратор при явно настроенной прямой
  адресации. Рабочий endpoint атомарно подтверждает admission.
- Processing services не зависят от RabbitMQ или другого брокера.
- Временное хранилище принадлежит AI Core.
- Постоянное хранилище находится вне AI Core.
- Передача файлов — только через службу временных файлов по коротким ссылкам;
  произвольные внешние URL и отдельный предварительный URL-checker запрещены.
- Исходные URL из задания являются единственным исключением: оркестратор
  передаёт их закрытому import endpoint службы временных файлов, которая сама
  проверяет allowlist, соединение и поток. Processing services этих URL не видят.
- Служба временных файлов технически проверяет поток до публикации, а каждая
  processing service повторно ограничивает и проверяет декодирование на своей
  границе.
- Новый этап требует HTTP-договора службы и перехода состояния оркестратора.
