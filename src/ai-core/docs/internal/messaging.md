# Внутренние сообщения AI Core

Этот файл — единственный источник имён очередей, общей оболочки, доставки и
версионирования сообщений RabbitMQ. Полезная нагрузка принадлежит договору
соответствующей службы.

## Очереди воркеров

| Воркер | Команды | Результаты |
| --- | --- | --- |
| Подготовка | `ai.photo.prepare.commands` | `ai.photo.prepare.results` |
| Стилист | `ai.outfit.style.commands` | `ai.outfit.style.results` |
| Генерация | `ai.image.generate.commands` | `ai.image.generate.results` |
| Проверка | `ai.image.verify.commands` | `ai.image.verify.results` |
| Очистка | `ai.temporary.cleanup.commands` | `ai.temporary.cleanup.results` |
| Уведомления | `ai.status.notify.commands` | `ai.status.notify.results` |

Для каждой очереди команд существует отдельная очередь окончательно не
обработанных сообщений. Главный оркестратор публикует все команды и читает все
результаты. Каждый воркер читает только свою очередь команд и пишет только в свою
очередь результатов. Один RabbitMQ распределяет команды между свободными копиями
соответствующего воркера, в том числе на разных хостах.

## Общая оболочка

```json
{
  "message_id": "67b6fd73-9699-4e50-8cc0-7fd1865ed46a",
  "message_type": "worker.image.generate.command",
  "schema_version": "1.0",
  "job_id": "c84dfb50-f331-4c12-88f5-3c1a3e6015aa",
  "worker_run_id": "c9f5ad1d-b484-457f-829b-fd90d6f58ac8",
  "result_index": 3,
  "attempt": 2,
  "lease_token": 17,
  "correlation_id": "56912f8e-846e-409a-b894-d7f7b5834607",
  "created_at": "2026-09-27T10:00:00Z",
  "payload": {}
}
```

| Поле | Значение |
| --- | --- |
| `message_id` | Идемпотентность одного сообщения |
| `message_type` | Тип команды или результата |
| `schema_version` | Версия оболочки и полезной нагрузки |
| `job_id` | Задание AI Core |
| `worker_run_id` | Конкретная команда воркеру |
| `result_index` | Обязательно только для команды конкретного изображения; от `0` до `N - 1`. Для подготовки, очистки и уведомления отсутствует |
| `attempt` | Продуктовая или модельная попытка команды |
| `lease_token` | Защита от устаревшего результата |
| `correlation_id` | Связь команды и ответа |
| `created_at` | Время создания в UTC |
| `payload` | Данные договора конкретной службы |

## Доставка

- Очереди и сообщения сохраняются на диске.
- Издатель ждёт подтверждение RabbitMQ.
- Главный оркестратор подтверждает результат после сохранения состояния. Воркер
  подтверждает команду после публикации результата с подтверждением RabbitMQ.
- Доставка выполняется как минимум один раз.
- Главный оркестратор не применяет результат с тем же `message_id` второй раз.
- Воркер без собственной базы может повторно выполнить доставленную команду.
  Поэтому внешние эффекты договора воркера идемпотентны: запись временного файла
  неизменяема, уведомление имеет стабильный `event_id`, повторное удаление
  отсутствующего файла считается успешным.
- `prefetch` ограничивает число команд, одновременно выданных одной копии.

## Повторы

Повторная доставка RabbitMQ сохраняет тот же `message_id`, `worker_run_id`,
`lease_token` и `attempt`.
Новую продуктовую или модельную попытку создаёт только главный оркестратор с
новыми `message_id`, `worker_run_id` и `lease_token`. Неверная схема не
повторяется автоматически и попадает в очередь ошибок.

## Совместимость

Добавление необязательного поля совместимо в пределах старшей версии. Удаление
поля, изменение типа или смысла создаёт новую старшую версию. Во время обновления
получатель поддерживает текущую и предыдущую версии.
