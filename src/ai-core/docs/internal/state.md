# Состояние AI Core

Этот файл — единственный источник истины для владения состоянием, структуры базы
и восстановления. Правила доставки сообщений находятся в
[messaging.md](messaging.md).

## Владельцы

| Состояние | Единственный владелец |
| --- | --- |
| Задание, порядок этапов, конечное состояние и место результата | Главный оркестратор |
| Резервирование `OutfitSpec` | Главный оркестратор |
| Команда воркеру, срок и продуктовая попытка | Главный оркестратор |
| Входящие результаты и исходящие команды | Главный оркестратор |
| Веса модели и рабочий кэш процесса | Соответствующий воркер |

Существует одна база PostgreSQL главного оркестратора. Воркеры не имеют к ней
доступа и не создают собственных баз. Внешний интерфейс AI Core получает состояние только через
[внутренний договор](blocks/orchestration/main-orchestrator/CONTRACT.md).

## База главного оркестратора

### `ai_jobs`

`job_id`, хеш ключа идемпотентности, состояние, запрошенное и принятое количество,
версия договора, время, ошибка, отмена и подтверждение получения результатов.

### `ai_job_images`

Номер результата, состояние, зарезервированный комплект, число запусков,
воспроизводимые параметры модели, принятый `artifact_id` и последняя ошибка.

### `ai_worker_runs`

`worker_run_id`, вид воркера, место результата, номер попытки, состояние,
`lease_token`, срок выполнения, версия воркера и итог. Уникальность
`worker_run_id` не позволяет применить результат дважды.

### `ai_outfits`

Нормализованный хеш и состояние резерва комплекта. Уникальное ограничение не
позволяет принять повтор внутри задания.

### `ai_status_events`

Неизменяемые `event_id`, `job_id`, `sequence`, состояние и время события.

### `ai_artifacts`

`artifact_id`, `job_id`, `worker_run_id`, назначение, место результата, внутренний
ключ временного объекта, контрольная сумма, размер, формат, срок доступности,
состояние передачи и состояние удаления. Ограниченные ссылки в базе не хранятся.
Уникальность `(job_id, worker_run_id, purpose, slot)` не позволяет двум файлам
занять одно место. Жизненный цикл определён в [artifacts.md](artifacts.md).

### `inbox` и `outbox`

`inbox` хранит уже применённые `message_id` результатов. `outbox` хранит команды
и события до подтверждённой публикации в RabbitMQ. Запись изменения задания и
исходящего сообщения выполняется одной транзакцией.

## Аренда и устаревшие ответы

Для каждой команды главный оркестратор создаёт `worker_run_id` и монотонный
`lease_token`. Результат принимается только для текущей аренды. Поздний ответ
сохраняется как устаревший и не меняет задание. Новый технический запуск после
истечения срока получает новые идентификаторы; повторная доставка RabbitMQ того
же сообщения не считается новой попыткой.

## Восстановление

После запуска главный оркестратор:

1. публикует неотправленные записи `outbox`;
2. находит истёкшие аренды;
3. создаёт новую попытку только для незавершённой работы;
4. не применяет повторный `message_id` второй раз;
5. не повторяет уже принятые результаты.

Условие завершения берётся только из
[публичного договора](../public/ai-core-api/CONTRACT.md#завершённое-задание).

## Отмена

Главный оркестратор применяет отмену из
[публичного договора](../public/ai-core-api/CONTRACT.md#отмена), прекращает создавать команды
и помечает активные `worker_run_id` отменёнными. Даже при задержке сообщения он не
принимает поздний итог.
