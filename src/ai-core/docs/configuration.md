# Настройки AI Core

## 1. Общие правила

Каждый микросервис имеет свой набор переменных окружения и свой файл-пример для
локального запуска. Настоящие секреты не хранятся в Git. При неверной обязательной
настройке служба не запускается и сообщает понятную причину без значения секрета.

Ограничения AI Core принадлежат AI Core, а основной сервер подстраивается под
опубликованный договор. Диапазон количества результатов можно менять настройками
без изменения формата запроса.

## 2. Общие настройки всех служб

| Переменная | Начальное значение | Назначение |
| --- | ---: | --- |
| `AI_CORE_SERVICE_NAME` | обязательно | Имя службы в журналах и показателях |
| `AI_CORE_ENVIRONMENT` | `local` | Окружение запуска |
| `AI_CORE_LOG_LEVEL` | `INFO` | Уровень технических журналов |
| `AI_CORE_RABBITMQ_URL` | обязательно | Секретная строка подключения к RabbitMQ |
| `AI_CORE_RABBITMQ_PREFETCH` | `1` | Число одновременно взятых сообщений одной копией службы |
| `AI_CORE_MESSAGE_SCHEMA_VERSION` | `1.0` | Поддерживаемая версия договора сообщений |

Службе API доступ к RabbitMQ не обязателен. Главный и групповые оркестраторы имеют
разные строки подключения к своим базам. Каждая группа использует отдельную
учётную запись RabbitMQ с правами только на свои очереди.

## 3. Служба API

| Переменная | Начальное значение | Назначение |
| --- | ---: | --- |
| `AI_CORE_INTERNAL_TOKEN` | обязательно | Служебный токен основного сервера |
| `AI_CORE_ORCHESTRATOR_URL` | обязательно | Адрес внутреннего интерфейса главного оркестратора |
| `AI_CORE_REQUEST_TIMEOUT_SECONDS` | `10` | Ограничение внутреннего запроса |
| `AI_CORE_MIN_IMAGE_COUNT` | `1` | Минимальное количество изображений |
| `AI_CORE_MAX_IMAGE_COUNT` | `10` | Максимальное количество изображений |
| `AI_CORE_INPUT_URL_MIN_TTL_SECONDS` | `600` | Минимальный остаточный срок ссылки на исходник |

## 4. Главный оркестратор

| Переменная | Начальное значение | Назначение |
| --- | ---: | --- |
| `AI_CORE_DATABASE_URL` | обязательно | Секретная строка подключения к PostgreSQL |
| `AI_CORE_OUTBOX_INTERVAL_MS` | `250` | Частота публикации сохранённых команд |
| `AI_CORE_STAGE_TIMEOUT_SECONDS` | `600` | Базовый срок одной попытки этапа |
| `AI_CORE_MAX_ATTEMPTS_PER_IMAGE` | `3` | Максимум генераций одного места результата |
| `AI_CORE_MAX_ACTIVE_JOBS` | `100` | Защита от перегрузки всего конвейера |
| `AI_CORE_TEMP_DATA_TTL_HOURS` | `24` | Срок хранения временных данных после завершения |

Для разных этапов допускаются отдельные сроки выполнения. Они добавляются как
переменные конкретного этапа после измерений и не меняют договор сообщений.

## 5. Групповые оркестраторы

| Переменная | Начальное значение | Назначение |
| --- | ---: | --- |
| `AI_CORE_GROUP_NAME` | обязательно | Имя функциональной группы |
| `AI_CORE_GROUP_DATABASE_URL` | обязательно | Строка подключения к базе этой группы |
| `AI_CORE_GROUP_STAGE_QUEUE` | обязательно | Очередь команд от главного оркестратора |
| `AI_CORE_GROUP_RESULT_QUEUE` | обязательно | Очередь итогов главному оркестратору |
| `AI_CORE_WORKER_COMMAND_QUEUE` | обязательно | Очередь команд своим воркерам |
| `AI_CORE_WORKER_RESULT_QUEUE` | обязательно | Очередь результатов своих воркеров |
| `AI_CORE_WORKER_ATTEMPT_TIMEOUT_SECONDS` | `600` | Срок одной попытки воркера |
| `AI_CORE_GROUP_MAX_ATTEMPTS` | `3` | Максимум технических попыток этапа |

Каждая группа задаёт собственные сроки и пределы после измерений. Оркестратор
группы не получает строку подключения к общей базе заданий.

## 6. Воркеры моделей

| Переменная | Начальное значение | Назначение |
| --- | ---: | --- |
| `AI_CORE_WORKER_CONCURRENCY` | `1` | Число параллельных команд одной копии |
| `AI_CORE_MODEL_NAME` | обязательно | Имя модели |
| `AI_CORE_MODEL_VERSION` | обязательно | Точная версия модели |
| `AI_CORE_MODEL_ENDPOINT` | нет | Адрес процесса модели, если он отделён от обработчика очереди |
| `AI_CORE_MODEL_TIMEOUT_SECONDS` | `600` | Ограничение одного вызова модели |

Стилист, генератор и проверка имеют разные значения этих переменных и разные
образы развёртывания. Изменение одной модели не требует обновления других служб.

## 7. Воркер уведомлений

| Переменная | Начальное значение | Назначение |
| --- | ---: | --- |
| `AI_CORE_STATUS_CALLBACK_URL` | обязательно | Доверенный адрес основного сервера |
| `AI_CORE_STATUS_CALLBACK_SECRET` | обязательно | Секрет подписи уведомления |
| `AI_CORE_STATUS_CALLBACK_TIMEOUT_SECONDS` | `10` | Ограничение одной отправки |
| `AI_CORE_STATUS_CALLBACK_MAX_ATTEMPTS` | `10` | Максимум автоматических повторов доставки |

Адрес уведомлений задаёт оператор AI Core. Пользователь не может передать или
изменить его в запросе.

## 8. Хранение и очистка

Воркеры подготовки, генерации, проверки и очистки получают временные ссылки в
команде. Постоянные ключи доступа к общему хранилищу им не выдаются. Если для
воркера очистки требуется отдельная служебная роль, она ограничивается только
временной областью AI Core.

## 9. Локальная разработка

Файлы `.env` можно использовать локально, но нельзя добавлять в Git. В
репозитории допускаются только файлы `.env.example` без секретов. При запуске в
журнал выводятся имена и несекретные настройки, но не строки подключения, токены,
подписи и временные ссылки.
