# Подключение AI Core к любому backend

## Что требуется

1. Получить у поставщика AI Core базовый HTTP-адрес и сетевой доступ к API и URL результатов.
2. Согласовать origin ссылок на исходные фотографии: точные схему, hostname и порт.
3. Предоставлять фотографии по временным HTTP URL, доступным AI Core без дополнительных
   заголовков авторизации и без перенаправлений. Подписанные query-параметры допустимы.
4. Организовать постоянное хранение результатов в своём backend.

API предназначен для server-to-server вызовов в закрытой сети. Пользовательские
JWT, идентификаторы пользователей и cookies в AI Core не передаются. На уровне
этого API заголовок авторизации не требуется. Не вызывайте его напрямую из браузера.
Правила доступа пользователей к фотографиям определяет ваш backend.

## Последовательность интеграции

1. Вызвать `GET /health/ready` и `GET /v1/capabilities`.
   Готовность API не гарантирует успешного завершения каждого задания.
2. Проверить параметры по capabilities. Сохранить у себя исходное тело запроса и
   уникальный `Idempotency-Key` до отправки.
3. Вызвать `POST /v1/jobs`. Сохранить `job_id` и `status_url` из ответа `201` или `200`.
4. Опросом `GET /v1/jobs/{job_id}` дождаться конечного состояния.
   Webhook и callback в этом договоре отсутствуют.
5. При `FAILED` обработать `error`; при `CANCELLED` завершить ожидание.
6. При `COMPLETED` и `result_delivery_status=AVAILABLE` скачать все `results`.
   Проверить количество, индексы, размер и SHA-256 каждого файла.
7. Надёжно сохранить все файлы и связь со своим заданием. Защитить повторное
   сохранение от дубликатов по `job_id` и `artifact_id`.
8. Только после сохранения всех файлов отправить
   `POST /v1/jobs/{job_id}/results/ack` без тела и дождаться `204`.

Не считайте `COMPLETED` подтверждением сохранения в вашем backend. Начинайте
скачивание сразу после получения `AVAILABLE`: в текущей версии файлы могут стать
недоступны раньше `results_available_until`, а статус ещё оставаться `AVAILABLE`.
См. [ограничение срока доставки](CONTRACT.md#срок-доставки-в-текущей-версии).
После ACK повторное скачивание не гарантируется.

## Минимальный пример

Адреса и сроки в примерах — заглушки. Разместите реальные фотографии на согласованном
origin и укажите действительный `expires_at`; дата в JSON сама по себе не продлевает ссылку.

```sh
export AI_CORE_URL='http://ai-core.example:8001'
curl --fail-with-body "$AI_CORE_URL/v1/capabilities"
curl --fail-with-body "$AI_CORE_URL/health/ready"
curl --fail-with-body -X POST "$AI_CORE_URL/v1/jobs" \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: example-request-001' \
  --data-binary @request.json
```

Содержимое `request.json` приведено в [контракте](CONTRACT.md#создание-задания).
Если capabilities требует `drape_test`, используйте пример полного теста из
[набора примеров](../../../examples/README.md).

```sh
export JOB_ID='c84dfb50-f331-4c12-88f5-3c1a3e6015aa'
curl --fail-with-body "$AI_CORE_URL/v1/jobs/$JOB_ID"
# Только после скачивания, проверки и постоянного сохранения всех файлов:
curl --fail-with-body -X POST "$AI_CORE_URL/v1/jobs/$JOB_ID/results/ack"
```

## Повторы и восстановление

- Потеря HTTP-ответа не означает, что создание не состоялось. Повторяйте POST
  с прежним ключом и тем же телом, включая URL и `expires_at`.
- Изменение тела требует нового ключа. Не заменяйте ссылки под прежним ключом.
- Проверка срока ссылок применяется и к повторному POST: при недостаточном TTL
  возможен `400 INVALID_REQUEST`, даже если задание ранее было создано.
  Если `job_id` уже сохранён, продолжайте GET, а не повторное создание.
- Повтор POST для уже завершённого задания с доставкой `AVAILABLE` в текущей версии
  возвращает `503 SERVICE_UNAVAILABLE`. При известном `job_id` перейдите к GET.
  Если идентификатор потерян, зафиксируйте неопределённый результат и обратитесь к
  поставщику API: повтор не восстанавливает ID в этом состоянии. Новый ключ может
  создать дубликат, даже если прежний POST вернул ошибку.
- После перезапуска продолжайте опрос сохранённых заданий и незавершённое сохранение файлов.
- Для опроса используйте паузу, например 2–5 секунд, и увеличивайте её при сбоях.
  Это рекомендация клиенту, а не гарантированное время обработки.
- При `429` и `503` операций API учитывайте `Retry-After` в секундах. При потере
  соединения используйте ограниченные повторы с увеличением паузы и случайным разбросом.
- `FAILED` — окончательное состояние. `retryable=true` допускает новую попытку
  отдельным заданием с новым ключом; прежнее задание не возобновляется.
- Потерянный ответ ACK допускает повтор ACK. Если GET уже показывает `ACKNOWLEDGED`,
  проверьте собственную сохранённую копию и не начинайте генерацию заново автоматически.
- Если ответ создания потерян, `job_id` неизвестен, а прежние ссылки уже не проходят
  проверку TTL, API не предоставляет поиска задания по `Idempotency-Key`.
  Не считайте новый ключ безопасным повтором: он может создать второе задание.
  Зафиксируйте неопределённый результат и согласуйте восстановление с поставщиком API.
- При `404` скачивания и всё ещё `AVAILABLE` учитывайте известное ограничение срока:
  повтор GET не восстанавливает файл. Не отправляйте ACK без полного набора;
  прекратите бесконечные повторы и обработайте доставку как неуспешную.

## Приёмка интеграции

Проверьте создание и повтор с тем же ключом, конфликт изменённого тела, все конечные
состояния, отмену, `429`/`503`, потерю ответа POST и ACK, перезапуск клиента,
недоступную входную ссылку, истечение срока результатов и несовпадение checksum.
При неполном скачивании или ошибке сохранения ACK отправляться не должен.
Число файлов берите из задания: оно не фиксировано на пяти или десяти.
Формат берите из `results[].format`: предположение, что все результаты WebP, неверно.
Проверяйте и расширение, и Content-Type сохранённого файла. Приёмка вашего backend
должна подтвердить поддержку фактического формата, восстановление после потерянного
ACK и обработку `404` файла при всё ещё `AVAILABLE`. Эти требования не означают,
что любой существующий клиент уже им соответствует.

Подробности: [HTTP-контракт](CONTRACT.md), [ошибки](ERRORS.md).
