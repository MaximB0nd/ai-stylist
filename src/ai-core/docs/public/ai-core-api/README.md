# Внешний интерфейс AI Core

Этот документ описывает договор и границы будущей службы. Реализация внешнего
интерфейса и его подключение к основному серверу выполняются отдельно.

## Для чего создан

Единая внутренняя HTTP-точка входа основного сервера в AI Core. Интерфейс
публичен для клиентов AI Core, но не доступен конечному пользователю и не
принимает пользовательскую авторизацию.

Служба изолирует основной сервер от внутренних договоров, служб и очередей AI
Core. После подключения главного оркестратора она будет передавать ему
приведённые запросы и преобразовывать ответы во внешний формат.

## Функции

- проверяет служебный Bearer-токен;
- проверяет `Idempotency-Key`, JSON и все поля внешнего запроса;
- приводит допустимый запрос к одному внутреннему представлению;
- предоставляет создание, чтение состояния, отмену и подтверждение получения
  результатов;
- сообщает поддерживаемые ограничения через `GET /v1/capabilities`;
- сообщает живость процесса и готовность обслуживать задания;
- возвращает безопасные ошибки без внутренних данных.

## Владелец проверки входа

Внешний интерфейс — единственный владелец внешнего HTTP-договора. Он проверяет
авторизацию, структуру, типы, диапазоны, перечисления, идентификаторы и свойства
короткоживущих ссылок, которые можно проверить без скачивания файла.

Основной сервер может повторять эти проверки для быстрого ответа пользователю,
но его проверка не заменяет проверку на границе AI Core. Проверка состояния
задания и идемпотентности по сохранённым данным принадлежит главному
оркестратору. Проверка байтов и содержимого фотографий принадлежит отдельным
службам обработки изображений.

Отдельная общая служба проверки входных данных не используется: она дублировала
бы внешний договор и добавляла сетевой вызов без отдельного владельца данных.

## Поведение до подключения оркестратора

Служба должна запускаться независимо от главного оркестратора. После реализации
службы, пока клиент оркестратора не настроен или оркестратор недоступен:

- проверка авторизации и входного запроса продолжает работать;
- `GET /v1/capabilities` и проверка живости доступны;
- проверка готовности возвращает неготовность;
- корректная операция над заданием возвращает `503 SERVICE_UNAVAILABLE`;
- служба не создаёт фиктивный `job_id` и не сохраняет задания в памяти или БД.

## Не выполняет

- не принимает байты изображений и `multipart/form-data`;
- не скачивает ссылки и не проверяет содержимое фотографий;
- не хранит состояние заданий и не реализует идемпотентность по сохранённым
  данным;
- не управляет этапами, повторами и переходами состояния;
- не отправляет уведомления основному серверу;
- не обращается к PostgreSQL, RabbitMQ, постоянному или временному S3;
- не вызывает processing services и службу временных файлов;
- не выполняет обработку изображений и вызовы моделей.
