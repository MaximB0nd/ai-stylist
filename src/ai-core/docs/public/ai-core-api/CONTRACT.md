# Договор внешнего интерфейса AI Core

Документ задаёт поведение будущей HTTP-службы. Он не означает, что служба уже
реализована или подключена к основному серверу.

## Назначение и транспорт

Интерфейс связывает основной сервер продукта с AI Core. Он доступен только во
внутренней сети и не является пользовательским API.

| Правило | Значение |
| --- | --- |
| Сеть | внутренняя, HTTP |
| Формат | `application/json` |
| Авторизация | не требуется; доступ ограничивается внутренней сетью |
| Идентификатор пользователя | не передаётся |
| Передача изображений | HTTP URL разрешённого origin |
| Количество результатов | обязательное поле `requested_image_count`, `1..10` |
| Частичный успех | запрещён |

Неизвестные поля запрещены.
Числа передаются JSON-числами, а не строками. Байты фотографий и
`multipart/form-data` интерфейс не принимает.

## Возможности

```text
GET /v1/capabilities
```

Эндпоинт должен быть доступен независимо от подключения оркестратора и возвращать
ограничения, которые основной сервер должен применять при формировании запроса.

```json
{
  "api_version": "v1",
  "requested_image_count": {
    "minimum": 1,
    "maximum": 10
  },
  "input_urls": {
    "schemes": ["http"],
    "min_ttl_seconds": 900
  },
  "person": {
    "age": {"minimum": 1, "maximum": 120},
    "height_cm": {"minimum": 80, "maximum": 240},
    "gender": ["male", "female"]
  },
  "preferences": {
    "occasion": ["street", "study", "office", "evening"],
    "style": ["minimal", "classic", "casual", "romantic"],
    "shoe": ["sneakers", "loafers", "heels", "boots"],
    "mood": ["confident", "elegant", "relaxed", "bright"]
  }
}
```

`min_ttl_seconds` задаётся конфигурацией службы; пример показывает начальное
значение. Проверка запроса использует значение, возвращаемое текущим экземпляром
службы.

## Проверки состояния службы

```text
GET /health/live
GET /health/ready
```

- `live` возвращает `200`, если процесс способен отвечать на HTTP-запросы;
- `ready` возвращает `200`, только если настроен и доступен обязательный клиент
  главного оркестратора;
- после реализации службы, до подключения оркестратора `ready` возвращает `503`;
- проверки состояния не выполняют операции над заданиями и не запускают
  обработку изображений.

```json
{
  "status": "ok"
}
```

При неготовности:

```json
{
  "status": "not_ready"
}
```

## Создание задания

```text
POST /v1/jobs
Idempotency-Key: <непустой непрозрачный ключ до 255 символов>
```

```json
{
  "requested_image_count": 5,
  "inputs": {
    "face": {
      "url": "http://files.example/temporary-face",
      "expires_at": "2099-01-01T00:00:00Z"
    },
    "body": {
      "url": "http://files.example/temporary-body",
      "expires_at": "2099-01-01T00:00:00Z"
    }
  },
  "person": {
    "age": 16,
    "height_cm": 172,
    "gender": "female"
  },
  "preferences": {
    "occasion": "office",
    "style": "minimal",
    "shoe": "loafers",
    "mood": "confident"
  }
}
```

Поля `weight`, `description`, `user_id` и любые другие дополнительные данные не
входят в договор.

### Проверка запроса

| Поле | Ограничение |
| --- | --- |
| `Idempotency-Key` | обязателен, непустой, не более 255 символов |
| `requested_image_count` | целое число, `1..10` |
| `inputs.face`, `inputs.body` | обязательные объекты с `url` и `expires_at` |
| `url` | абсолютный HTTP URL до 4096 символов без `userinfo` и fragment; схема, hostname и порт точно совпадают с разрешённым origin из конфигурации |
| `expires_at` | RFC 3339; остаток не меньше текущего `min_ttl_seconds` |
| `person.age` | целое число, `1..120` |
| `person.height_cm` | целое число, `80..240` |
| `person.gender` | `male` или `female` |
| `preferences.occasion` | одно допустимое значение |
| `preferences.style` | одно допустимое значение |
| `preferences.shoe` | одно допустимое значение |
| `preferences.mood` | одно допустимое значение |
| запрещённая схема, origin, `userinfo` или fragment URL | `422 INPUT_URL_NOT_ALLOWED` |
| другое неизвестное или неверное поле | `400 INVALID_REQUEST` |

Допустимые предпочтения совпадают с текущей формой основного приложения:

| Поле | Значения |
| --- | --- |
| `occasion` | `street`, `study`, `office`, `evening` |
| `style` | `minimal`, `classic`, `casual`, `romantic` |
| `shoe` | `sneakers`, `loafers`, `heels`, `boots` |
| `mood` | `confident`, `elegant`, `relaxed`, `bright` |

Служба разбирает URL стандартной библиотекой и сравнивает origin в каноническом
виде, но не выполняет DNS-проверку и не соединяется с адресом. После создания
задания оркестратор поручает службе временных файлов потоково импортировать оба
входа. Artifact service повторяет проверку непосредственно при соединении и
проверяет формат, размер и декодирование; предметную пригодность фотографий
проверяют специализированные processing services. Они получают только
внутренние ссылки и не видят исходные URL основного сервера.

### Приведение и идемпотентность

После проверки внешний интерфейс:

1. формирует каноническое внутреннее представление без дополнительных полей;
2. вычисляет SHA-256 канонического запроса;
3. вычисляет SHA-256 исходного `Idempotency-Key`;
4. передаёт оба хеша и приведённый запрос главному оркестратору.

Исходный ключ не журналируется и не хранится. Решение о повторе принимает
главный оркестратор по сохранённым хешам:

| Условие | Результат после подключения оркестратора |
| --- | --- |
| новый ключ | создать задание |
| тот же ключ и то же приведённое тело | вернуть прежнее задание |
| тот же ключ и другое приведённое тело | `409 IDEMPOTENCY_CONFLICT` |

До подключения оркестратора корректный запрос возвращает `503` и не создаёт
задание.

### Успешный ответ после подключения оркестратора

```json
{
  "job_id": "c84dfb50-f331-4c12-88f5-3c1a3e6015aa",
  "status": "QUEUED",
  "requested_image_count": 5,
  "status_url": "/v1/jobs/c84dfb50-f331-4c12-88f5-3c1a3e6015aa"
}
```

Новый запрос возвращает `201`. Идемпотентный повтор существующего запроса
возвращает `200`.

## Получение состояния

```text
GET /v1/jobs/{job_id}
```

`job_id` должен быть UUID. После подключения оркестратора ответ представляет его
состояние во внешнем формате.

```json
{
  "job_id": "c84dfb50-f331-4c12-88f5-3c1a3e6015aa",
  "status": "PROCESSING",
  "requested_image_count": 5,
  "accepted_image_count": 3,
  "failed_attempt_count": 1,
  "updated_at": "2026-10-05T10:30:00Z",
  "error": null
}
```

Состояния: `QUEUED`, `PROCESSING`, `COMPLETED`, `FAILED`, `CANCELLED`.

Конечные состояния: `COMPLETED`, `FAILED`, `CANCELLED`.

До подключения оркестратора синтаксически корректный запрос возвращает `503`.

При `FAILED` поле `error` содержит безопасные `code`, `message` и `retryable`.
Для отклонённой фотографии оно дополнительно содержит массив `reasons` из
стабильных кодов проверки лица или полного роста; элементы уникальны, их порядок
не задан. При остальных ошибках `reasons` отсутствует. Возможные коды
предобработки: `FACE_PHOTO_REJECTED`, `BODY_PHOTO_REJECTED`,
`IDENTITY_MISMATCH`, `PHOTO_UNPROCESSABLE`, `COLOR_TYPE_UNCERTAIN` и
`PREPROCESSING_UNAVAILABLE`. Точное соответствие внутренним результатам
определяет [договор оркестратора](../../internal/services/main-orchestrator/CONTRACT.md#решения-предобработки-и-повторы).

## Завершённое задание

```json
{
  "job_id": "c84dfb50-f331-4c12-88f5-3c1a3e6015aa",
  "status": "COMPLETED",
  "requested_image_count": 1,
  "accepted_image_count": 1,
  "result_delivery_status": "AVAILABLE",
  "results_available_until": "2026-10-06T10:00:00Z",
  "results": [
    {
      "order_index": 0,
      "artifact_id": "01J8Z8Y7W6V5T4S3R2Q1P0N9M8",
      "download_url": "http://temporary-files.example/artifacts/01J8Z8Y7W6V5T4S3R2Q1P0N9M8/read",
      "checksum_sha256": "sha256:example-0",
      "size_bytes": 1048576,
      "format": "webp",
      "width": 1024,
      "height": 1536,
      "model_version": "image-model@example",
      "prompt_version": "photographer-v1",
      "outfit_spec_version": "1.0",
      "seed": 12345
    }
  ],
  "error": null
}
```

| `result_delivery_status` | `results` | Значение |
| --- | --- | --- |
| `AVAILABLE` | метаданные и ссылки | можно скачать |
| `ACKNOWLEDGED` | `[]` | основной сервер подтвердил сохранение |
| `EXPIRED` | `[]` | срок истёк до ACK |

- `COMPLETED` содержит ровно `requested_image_count` результатов.
- Повторный `GET` при `AVAILABLE` возвращает ссылку на тот же `artifact_id`.
- После `ACKNOWLEDGED` или `EXPIRED` состояние остаётся `COMPLETED`.
- Постоянное хранение находится вне AI Core.

## Подтверждение получения результатов

```text
POST /v1/jobs/{job_id}/results/ack
```

Тело отсутствует. После подключения оркестратора:

| Условие | Ответ | Новое состояние доставки |
| --- | --- | --- |
| `AVAILABLE` до срока | `204` | `ACKNOWLEDGED` |
| повтор после ACK | `204` | `ACKNOWLEDGED` |
| после срока | `409 RESULTS_EXPIRED` | `EXPIRED` |

Смена `AVAILABLE` на `ACKNOWLEDGED` или `EXPIRED` атомарна и принадлежит
оркестратору: первая запись побеждает. До его подключения запрос возвращает
`503`.

## Отмена

```text
POST /v1/jobs/{job_id}/cancel
```

Тело отсутствует. После подключения оркестратора отмена идемпотентна и возвращает
внешнее представление задания в состоянии `CANCELLED`. Поздний внутренний
результат не меняет конечное состояние. До подключения оркестратора запрос
возвращает `503`.

## Передача результатов

После подключения полного процесса основной сервер:

1. получает метаданные и ссылки через `GET /v1/jobs/{job_id}`;
2. скачивает каждый результат через службу временных файлов;
3. проверяет `checksum_sha256`;
4. сохраняет файл постоянно и защищается от повтора по `artifact_id`;
5. отправляет ACK.

Байты не проходят через внешний интерфейс и главный оркестратор AI Core.
`download_url` является HTTP-ссылкой на временный файл.
Основной сервер получает изменения состояния опросом `GET /v1/jobs/{job_id}`.
AI Core не отправляет уведомления о состоянии задания.

## Ошибки

```json
{
  "error": {
    "code": "INVALID_REQUEST",
    "message": "Запрос не прошёл проверку",
    "retryable": false
  }
}
```

| HTTP | Код | Владелец и условие |
| ---: | --- | --- |
| `400` | `INVALID_REQUEST` | внешний интерфейс: неверный JSON, заголовок, идентификатор или поле |
| `404` | `JOB_NOT_FOUND` | оркестратор после подключения: задание отсутствует |
| `409` | `IDEMPOTENCY_CONFLICT` | оркестратор после подключения: ключ использован с другим запросом |
| `409` | `INVALID_JOB_STATE` | оркестратор после подключения: операция запрещена состоянием |
| `409` | `RESULTS_EXPIRED` | оркестратор после подключения: ACK получен после срока |
| `422` | `INPUT_URL_NOT_ALLOWED` | внешний интерфейс: схема или origin входной ссылки запрещены |
| `422` | `UNSUPPORTED_INPUT` | служба обработки после подключения: файл или его содержимое не поддерживается |
| `429` | `TOO_MANY_REQUESTS` | внешний интерфейс или зависимость: превышен предел нагрузки |
| `500` | `INTERNAL_ERROR` | внешний интерфейс: непредвиденная внутренняя ошибка без раскрытия деталей |
| `503` | `SERVICE_UNAVAILABLE` | оркестратор не настроен, недоступен или обязательная зависимость не готова |

`429` и `503` содержат `Retry-After`. Ошибки не содержат URL,
пользовательский текст, содержимое фотографий, внутренние адреса или трассировки.

## Журналирование

Разрешены технические идентификаторы запроса, код операции, длительность, HTTP
статус и безопасный код ошибки. Запрещено журналировать:

- `Idempotency-Key`;
- URL фотографий и их параметры;
- тело запроса целиком;
- возраст, рост и пол;
- выбранные предпочтения;
- байты и метаданные изображений.
