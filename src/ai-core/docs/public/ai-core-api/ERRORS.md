# Ошибки AI Core и действия backend

## Ошибка HTTP-запроса

```json
{
  "error": {
    "code": "INVALID_REQUEST",
    "message": "Invalid request",
    "retryable": false
  }
}
```

| HTTP | Код | Действие клиента |
| --- | --- | --- |
| 400 | `INVALID_REQUEST` | проверить JSON, типы, заголовки, UUID, TTL ссылок и размер тела |
| 404 | `JOB_NOT_FOUND` | проверить сохранённый ID и окружение |
| 409 | `IDEMPOTENCY_CONFLICT` | не менять тело под прежним ключом; новое задание требует нового ключа |
| 409 | `INVALID_JOB_STATE` | перечитать состояние; операция уже недопустима |
| 409 | `RESULTS_EXPIRED` | файлы больше нельзя подтвердить; проверить собственную копию |
| 422 | `INPUT_URL_NOT_ALLOWED` | использовать согласованный HTTP origin без userinfo/fragment |
| 422 | `COLOR_DRAPE_REQUIRED` | добавить полный тест из согласованного каталога |
| 422 | `COLOR_DRAPE_CATALOG_UNAVAILABLE` | сверить ID/SHA-256 с capabilities |
| 422 | `UNSUPPORTED_INPUT` | заменить неподдерживаемые входные данные |
| 429 | `TOO_MANY_REQUESTS` | отложить запрос на `Retry-After` |
| 500 | `INTERNAL_ERROR` | сохранить контекст обращения; не создавать дубликат задания |
| 503 | `SERVICE_UNAVAILABLE` | отложить запрос на `Retry-After` |

У `429`/`503` операций заданий `retryable=true`, `Retry-After` задаётся в секундах.
Для остальных перечисленных HTTP-ошибок текущий ответ содержит `retryable=false`.
После сетевого сбоя POST результат неизвестен: повтор допустим только с прежними
ключом и телом. Не интерпретируйте временную ошибку GET как `FAILED` задания.

Исключения из формата: health endpoints используют `status`; ошибки скачивания —
Problem Details, см. [контракт](CONTRACT.md#скачивание). Неизвестный путь или неверный
HTTP-метод могут возвращать стандартное тело `detail` с `404`/`405`.
Не предполагается, что любой ошибочный ответ, в том числе сетевого посредника,
обязательно является JSON указанной структуры.

## Ошибка выполнения задания

GET существующего задания возвращает HTTP `200` даже при `status=FAILED`.
Пример поля `error` внутри такого ответа:

```json
{
  "code": "FACE_PHOTO_REJECTED",
  "message": "Processing failed",
  "retryable": false,
  "reasons": ["FACE_TOO_BLURRY"]
}
```

`retryable=true` означает возможность новой попытки отдельным заданием с новым
ключом, а не продолжение завершившегося задания. Учитывайте фактический флаг ответа.
Не повторяйте автоматически задания с `retryable=false`.
`reasons` может отсутствовать или быть `null`; при отклонении фотографии содержит
уникальные коды, порядок не является частью договора.

| Код | Значение и действие |
| --- | --- |
| `FACE_PHOTO_REJECTED` | заменить фото лица с учётом `reasons` |
| `BODY_PHOTO_REJECTED` | заменить фото полного роста с учётом `reasons` |
| `IDENTITY_MISMATCH` | предоставить две фотографии одного человека |
| `PHOTO_UNPROCESSABLE` | заменить повреждённый или неподдерживаемый файл |
| `COLOR_TYPE_UNCERTAIN` | цветовые данные недостаточны или противоречивы; уточнить фото/тест |
| `OUTFIT_UNAVAILABLE` | не удалось получить подходящий уникальный комплект; изменить предпочтения |
| `PREPROCESSING_UNAVAILABLE` | подготовка входных данных не завершилась; учитывать `retryable` |
| `PROCESSING_UNAVAILABLE` | обработка не завершилась; учитывать `retryable` |
| `GENERATION_UNAVAILABLE` | генерация недоступна; учитывать `retryable` |
| `CANDIDATES_REJECTED` | подходящие изображения не получены; не сохранять частичный результат |
| `VERIFICATION_INCONCLUSIVE` | качество результата не подтверждено; учитывать `retryable` |
| `INPUT_EXPIRED` | срок входных ссылок истёк; для нового задания подготовить новые ссылки |
| `JOB_EXPIRED` | истёк срок выполнения задания; завершить ожидание |
| `INPUT_URL_NOT_ALLOWED` | входная ссылка недопустима; исправить origin или свойства URL |
| `CHECKSUM_MISMATCH` | целостность данных не подтверждена |
| `ARTIFACT_URL_NOT_ALLOWED` | доступ к данным отклонён; обратиться к поставщику API |
| `VALIDATION_ERROR` | данные не прошли проверку |
| `INFERENCE_FAILED` | обработка изображения не завершилась |
| `MALFORMED_REQUEST` | ошибка формата данных при обработке |
| `REQUEST_TOO_LARGE` | превышен допустимый размер |
| `UNSUPPORTED_REQUEST_MEDIA_TYPE` | неподдерживаемый тип содержимого |

Список не закрытый: текущий API может возвращать другие коды. Неизвестный код
обрабатывайте как общий отказ с учётом `retryable`; сохраняйте его для диагностики,
не показывайте техническую строку пользователю вместо понятного сообщения.
Названия последних кодов не означают, что исходный внешний POST был отвергнут:
здесь речь о задании, которое уже было принято.

## Причины отклонения фотографий

| `reasons[]` | Подсказка пользователю |
| --- | --- |
| `FACE_NOT_FOUND` | лицо должно быть видно |
| `MULTIPLE_FACES` | на фото должно быть одно лицо |
| `FACE_TOO_SMALL` | сделать более крупный портрет |
| `FACE_TOO_BLURRY` | сделать резкое фото лица |
| `INVALID_FACE_POSE` | смотреть прямо, без сильного наклона |
| `INVALID_EXPOSURE` | избегать слишком тёмного кадра и пересвета |
| `UNEVEN_LIGHTING` | обеспечить равномерное освещение лица |
| `PERSON_NOT_FOUND` | человек должен быть различим |
| `MULTIPLE_PEOPLE` | в кадре должен быть один человек |
| `BODY_CROPPED` | поместить человека в кадр целиком |
| `BODY_OCCLUDED` | убрать предметы, закрывающие тело |
| `IMAGE_TOO_SMALL` | использовать изображение большего разрешения |
| `IMAGE_TOO_BLURRY` | сделать резкое фото полного роста |

Отказ не обязательно содержит все проблемы обеих фотографий. Отображайте полученные
причины, допускайте неизвестную причину и не требуйте определённого порядка массива.
