# AI Core

`AI Core` — независимый backend, который выполняет AI-задачи проекта. Он разворачивается и масштабируется отдельно от основного backend и взаимодействует с ним только через API-контракт.

![Архитектура AI Core](../../docs/ai-system-architecture.png)

Редактируемый исходник схемы: [ai-system-architecture.drawio](../../docs/ai-system-architecture.drawio).

Подробное описание генерационного конвейера: [Архитектура генерации образов](../../docs/image-generation-architecture.md).

## Граница ответственности

AI Core:

- принимает задание и необходимые входные данные через `AI Backend API`;
- ставит длительные операции в собственную AI-очередь;
- управляет порядком выполнения этапов, повторными попытками и ошибками;
- вызывает AI-анализатор внешности, AI-стилиста и AI-фотографа;
- проверяет `OutfitSpec` и итоговое изображение;
- возвращает статус, результат или ошибку основному backend.

AI Core не отвечает за:

- публичное API приложения;
- авторизацию и продуктовую бизнес-логику;
- основную базу данных;
- S3 и другое постоянное файловое хранилище;
- интерпретацию и сохранение результата после его возврата.

Основной backend сам решает, откуда получить входные данные, как передать их AI Core и что сделать с полученным результатом. Поэтому контракт AI Core не зависит от конкретной базы данных или файлового хранилища.

## Поток выполнения

1. `Backend Core` создаёт запрос через принадлежащий основному backend компонент `AI Request API`.
2. `AI Request API` передаёт задание и входные данные в `AI Backend API`.
3. `AI Backend API` помещает задание в AI-очередь.
4. `AI-оркестратор` получает задание и последовательно вызывает необходимые этапы конвейера.
5. Результат выполнения возвращается в AI-очередь.
6. `AI Backend API` возвращает статус, результат или ошибку через `AI Request API` в `Backend Core`.

Очередь и внутренние model-server'ы являются деталями реализации AI Core и не раскрываются внешним потребителям.

## Компоненты

| Компонент | Ответственность |
| --- | --- |
| `AI Backend API` | Единственная внешняя точка входа в AI Core |
| `AI-очередь` | Асинхронные задания, результаты и повторные попытки |
| `AI-оркестратор` | Управление этапами обработки и маршрутизация данных |
| `AI-анализатор внешности` | Получение признаков с помощью классификации и регрессии |
| `AI-стилист` | Формирование структурированного `OutfitSpec` с помощью Qwen3.5 и vLLM |
| `Проверка OutfitSpec` | Проверка структуры и ограничений выбранного образа |
| `AI-фотограф` | Генерация или редактирование изображения через vLLM-Omni |
| `Проверка изображения` | Контроль качества и соответствия результата заданию |

## Развёртывание

API, очередь и оркестратор запускаются независимо от основного backend. Model-server'ы также являются отдельными процессами или контейнерами:

- AI-стилист запускается на одной GPU и масштабируется независимыми репликами;
- AI-фотограф использует одну GPU или неделимую группу из нескольких GPU;
- один model-server обслуживает одну загруженную модель;
- замена модели или способа её распределённого запуска не изменяет внешний контракт AI Core.

Для MVP допускается запуск компонентов на одном хосте в разных контейнерах. При росте нагрузки их можно переносить на отдельные GPU-хосты без изменения основного backend.

## Контракт результата

Конкретный транспортный формат будет зафиксирован при реализации API, но архитектурно ответ содержит:

- идентификатор задания;
- состояние выполнения;
- структурированный `OutfitSpec` при успешном подборе;
- сгенерированный результат в согласованном представлении;
- диагностический код и безопасное описание ошибки при неуспешном выполнении.

AI Core не определяет, где результат будет храниться и как его покажут пользователю.
