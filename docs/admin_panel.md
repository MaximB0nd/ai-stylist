# Административная панель backend_core — MVP

## Назначение и границы

Панель находится в `backend_core`, пользовательский frontend и AI Core не меняются.
FastAdmin 0.10.0 с SQLAlchemy предоставляет таблицы данных. Обзор, список генераций,
карточка задачи, карточка пользователя и состояние сервисов реализованы небольшими
страницами backend. Таблицы пользователей и альбомов FastAdmin открываются внутри
общей оболочки. Отдельная сборка административного frontend не требуется.

Разделы: **Обзор**, **Генерации**, **Пользователи**, **Альбомы**, **Состояние сервисов**.
Отзывы, онлайн-присутствие, редактирование данных, перезапуск задач и сбор внутренних
метрик ИИ в MVP не входят. Все бизнес-данные доступны только для чтения.

## Включение через Docker Compose

Панель по умолчанию выключена. В корневом `.env` задайте:

```dotenv
ADMIN_ENABLED=true
ADMIN_SECRET_KEY=<отдельный случайный секрет длиной не меньше 32 символов>
ADMIN_COOKIE_SECURE=false
```

Получить случайный секрет можно командой:

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

Он должен отличаться от `SECRET_KEY` пользовательских JWT. Не добавляйте локальный
`.env` и сгенерированные секреты в Git. Для HTTPS установите `ADMIN_COOKIE_SECURE=true`;
в режиме production это проверяется конфигурацией. Для локального HTTP нужна `false`.

Из корня проекта:

```bash
docker compose up -d --build backend_core nginx
```

Миграция `0008` применяется существующей командой запуска backend. Она добавляет
`users.is_admin` и `albums.finished_at` с индексом. Данные сохраняются, удалять тома
Docker не требуется. Все существующие пользователи получают `is_admin=false`.

Зарегистрируйте отдельный аккаунт администратора через обычную регистрацию сайта,
затем назначьте ему роль локальной командой:

```bash
docker compose exec backend_core python -m app.admin.manage --email admin@example.com
```

Замените email на адрес нужной существующей учётной записи. Команда не создаёт
пароль, не выводит его и не добавляет публичный API назначения администраторов.
Неактивному аккаунту назначение роли запрещено.

Панель: `http://localhost:8081/admin/` при `NGINX_PORT=8081`. Вход — email и пароль
выбранного аккаунта. Для другого ПК используйте LAN IP сервера вместо localhost.
Nginx проксирует весь `/admin/`, включая FastAdmin API и статические ресурсы, в backend.
В Docker-образ включены закреплённые зависимости FastAdmin и psutil.

Отозвать доступ:

```bash
docker compose exec backend_core python -m app.admin.manage --email admin@example.com --revoke
```

Роль и активность проверяются при каждом защищённом запросе: снятие роли или блокировка
аккаунта прекращают доступ уже выданной сессии. Сессия панели отдельная от пользовательского
JWT, хранится в HttpOnly/SameSite=Strict cookie и действует час. Кнопка «Выйти» удаляет
cookie; это не индивидуальный серверный blacklist ранее скопированных токенов.
На вход действует ограничение 10 попыток в минуту на адрес подключения к backend;
за одним reverse proxy этот лимит может быть общим для администраторов.

Для запуска без Docker задайте аналогичные параметры в `src/backend_core/.env`,
затем из этой папки выполните `python -m alembic upgrade head`, назначьте роль
`python -m app.admin.manage --email ...` и запустите Uvicorn как обычно.

## Генерации и время

Источником остаётся существующая таблица `albums`; новой таблицы задач нет.
Техническая модель GenerationRecord FastAdmin отображает ту же таблицу.

Список `/admin/generations` показывает ID генерации, ID AI Core, статус, время создания,
длительность, последнее изменение записи и ошибку. Есть точный поиск по UUID,
фильтры статуса и диапазона дат создания (UTC), сортировка от новых задач и страницы по 25 строк.
Нажатие ID открывает карточку с пользователем, альбомом, параметрами, фактическим числом
сохранённых фото, запрошенным количеством из сохранённого dispatch_request,
планом следующей попытки и состоянием ACK. Подписанные исходные ссылки и JSON
dispatch_request не выдаются в таблицах и карточке. URL внутри диагностических ошибок скрываются.

Начало отсчёта — `Album.created_at`: приём задачи backend, а не начало обработки на GPU.
Для активной задачи длительность вычисляется до текущего момента; для финальной —
до `finished_at`. Это поле записывается при переходе в COMPLETED/FAILED, а сохранение
готовых фото и времени завершения выполняется одной транзакцией. Повторные события
и поздний ACK не продлевают завершённую генерацию.

Старые финальные записи не получают выдуманное время: `finished_at=NULL`, длительность
показывается как неизвестная. Они не входят в число завершений за последние 24 часа.
Последнее обновление записи не выдаётся за достоверный прогресс AI Core.

## Обзор, пользователи и альбомы

Обзор обновляется раз в 10 секунд: активные задачи по статусам, завершения и ошибки за
24 часа, самая долгая активная задача, последние 10 задач с диагностическими ошибками,
сводка состояния зависимостей. Ошибки могут быть временными и не означают FAILED.

FastAdmin показывает пользователей (ID, имя, email, активность, дата регистрации) и альбомы.
Карточка задачи содержит ссылку на карточку пользователя с последними 25 связанными
генерациями/альбомами. В таблице пользователя также есть details_url для этой карточки.
Хеши паролей исключены из сериализации. Изменения, удаление, действия, смена пароля
и экспорт запрещены серверными проверками панели.

В альбомах число сохранённых фотографий считается по таблице photos, а не по
историческому значению total_photos до завершения задачи. Готовые фотографии можно
просматривать в карточке генерации; подписанные публичные ссылки создаются при открытии.
При временном сбое MinIO карточка сохраняет метаданные и сообщает о недоступности фото.
Открывая панель с другого ПК, настройте MINIO_PUBLIC_ENDPOINT на LAN адрес MinIO.

## Состояние сервисов

Фоновая задача раз в 10 секунд сохраняет небольшой снимок в памяти процесса:

- доступность PostgreSQL и MinIO/бакета — существующие ограниченные по времени проверки;
- CPU процесса, RAM RSS в МБ, PID и время работы процесса;
- очередь **скачивания результатов**: ожидающие/лимит и занятые обработчики/лимит;
- последняя операция обращения к AI Core: create/poll/ack/cancel, время, длительность,
  HTTP-код либо тип сетевой ошибки. Данные старше 60 секунд помечены устаревшими.

Это наблюдение последнего запроса, а не полный health-check ИИ. Если обращений не было,
панель показывает отсутствие данных. Секреты, тела запросов и ответов и URL не собираются.
До первого измерения значения ресурсов и состояние зависимостей неизвестны.
CPU 100% соответствует одному логическому ядру и на нескольких ядрах может превышать 100%.

Метрики относятся к **одному процессу backend**, не ко всему ПК, PostgreSQL-контейнеру
или GPU ИИ. При перезапуске снимок сбрасывается. Текущая архитектура MVP рассчитана
на один процесс Uvicorn; для нескольких workers нужно общее хранилище/сборщик метрик.
История CPU/RAM, Prometheus, Grafana, трассировка каждого этапа и каждого фото не реализованы.

## Проверки

Из `src/backend_core`:

```bash
python -m pytest tests -q
```

`tests/test_admin.py` проверяет границы доступа, запрет изменений/экспорта,
исключение секретных полей, длительность и безопасную телеметрию.
`tests/test_admin_postgres.py` проверяет миграцию существующей БД, реальный вход FastAdmin,
отказ обычному пользователю, снятие роли и фиксацию времени завершения/ACK.
Он использует FEEDBACK_TEST_DATABASE_URL только для создания отдельной временной БД
с префиксом admin_test_; рабочие таблицы не мигрируются и не удаляются.

Браузерная проверка выполнена в Microsoft Edge на изолированной PostgreSQL: вход,
обзор, переход к задаче, таблицы пользователей и альбомов FastAdmin и страница сервисов.

Итоговая проверка: 313 passed, 2 skipped в локальном окружении и в собранном Linux-образе с отдельной PostgreSQL. Docker-сборка, Compose-конфигурация и nginx -t прошли.
