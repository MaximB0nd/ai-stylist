# Страница генерации (FRONT-10)

## Компоновка

Маршрут `/generation` использует общий `app_shell`. Реализация находится в
`src/frontend/src/pages/generation.py`, стили изолированы в
`public/css/pages/generation.css`. Слева сначала расположены четыре группы
визуальных ответов, затем возраст, рост и фотографии. Справа на desktop
находится сводка анкеты. Общий layout и другие страницы не изменяются.

Используются общие шрифты, палитра и элементы управления FRONT-15.
В каждой группе выбирается один вариант, как в актуальном HTML-макете.
Поля не заполняются вымышленными данными: примеры показаны в placeholder.

## Иллюстрации

17 WebP-файлов в `public/images/generation` извлечены без изменений из
`embeddedAssets` предоставленного владельцем проекта макета
`Носи-Красиво.html` от 7 сентября 2026 года. Это 16 иллюстраций ответов и
`photo06.webp`, сохранённое как пример для ручной проверки загрузки.
После UX-аудита декоративное фото убрано из сводки; на странице остаются
16 иллюстраций вариантов ответа и миниатюры выбранных вариантов в сводке.
Новые сторонние изображения не скачивались. Перед публичным запуском команда
должна подтвердить права на изображения исходного макета.

## Границы задачи

FRONT-10 не подключает API, авторизацию и создание альбомов. Основное действие
страницы проверяет анкету, но не имитирует успешную генерацию.

## Поведение и данные

`public/js/pages/generation.js` подключён из браузерного `main.js`.
Инициализация выполняется при загрузке и после `pp:navigation:complete`.
Старые обработчики снимаются через AbortController. Повторная инициализация
той же формы не создаёт дубликатов обработчиков.

- Обязательные числовые поля: возраст 1–120 и рост 80–240 см, целые числа.
  Вес убран по решению владельца проекта. Ограничения оставшихся полей
  взяты из макета и не являются медицинскими рекомендациями.
- Два отдельных фото: JPG, PNG или WebP, каждое до 10 МБ включительно.
  Кроме типа и размера проверяется возможность декодировать изображение.
- В каждой из четырёх групп выбирается один ответ. Доступен выбор клавиатурой.
  Высота иллюстраций 160 px; при ширине контейнера анкеты до 540 px сетка
  переключается на 2 столбца с высотой изображений 128 px.
- Сводка считает только корректные числовые поля, открытые фото и выбранные
  ответы. Максимальное заполнение: 8 из 8; JavaScript вычисляет его из формы.
- По кнопке «Проверить анкету» ошибки показываются рядом с полями, фокус
  переходит к первой ошибке в порядке расположения полей на странице.
  Успех означает только готовность анкеты.
- До проверки пустые поля не показывают ошибки при потере фокуса.
  Введённое неверное значение проверяется при выходе из поля. После проверки
  ошибки обновляются по мере исправления.
- Пока фото открывается, повторная проверка заблокирована. При быстрой замене
  устаревший результат декодирования не заменяет более новый выбор.
- Неверная замена сохраняет предыдущее корректное превью. Удаление очищает
  его и уменьшает счётчик; тот же файл можно выбрать повторно. Сохранение
  предыдущего фото явно указано в ошибке. Статусы открытия и готовности
  изображения доступны визуально и через live region.
- Поддерживается перетаскивание файла в каждую из двух зон. Несколько файлов
  за один раз отклоняются с пояснением; файлы не выбираются молча.
- Сводка «Ваш выбор» показывает общий прогресс, счётчики трёх разделов
  и миниатюры только выбранных ответов. Нажатие миниатюры переводит фокус
  к соответствующему ответу для изменения; доступное имя содержит его значение.
- Прогресс и основная кнопка стоят перед миниатюрами, поэтому добавление
  ответов не сдвигает действие вниз. Фотографии отображаются целиком в зоне
  высотой 220 px. Числовые поля имеют размер текста 16 px и общую ширину
  не более 520 px. Остальные подписи используют общий размер 14 px.

Фотографии представлены временными blob URL. Они освобождаются при замене,
удалении и уходе со страницы. Фото и параметры не сохраняются в localStorage,
не отправляются на сервер и не попадают в профиль. После ухода фотографии
нужно выбрать заново. При восстановлении страницы из browser cache старые
превью очищаются; числовые поля может восстановить сам браузер.

Перед подключением API потребуются согласование ограничений с backend,
серверная валидация и отдельная логика отправки. Текущая проверка в браузере
не заменяет проверку на сервере.

## Проверки

Из `src/frontend`:

```powershell
.\.venv\Scripts\python.exe -m ruff check src/pages/generation.py tests
.\.venv\Scripts\python.exe -m unittest discover -s tests
npm run test:unit
npm run build
```

Node-тесты используют встроенный `node:test`, без новых зависимостей и линтеров.
Дополнительно проверяется синтаксис `node --check public/js/main.js` и
`node --check public/js/pages/generation.js`.

Ручная проверка: пустая анкета, диапазоны и шаг чисел, клавиатурный выбор,
два фото, замена/удаление, неверный формат, повреждённый файл, превышение
10 МБ, успешная проверка 8/8, переход на главную и обратно.

Результат проверки после UX-аудита: 26 Python-тестов и 13 Node-тестов проходят;
Ruff, проверка синтаксиса JavaScript и сборка проходят. На desktop 1280,
1440 и 1920 px нет горизонтального переполнения и обрезанных подписей.
Иллюстрации загружаются, превью фото вписываются целиком в фиксированную зону.
Мобильная адаптация общего layout не входит в этот issue: на 390 px
сохраняется переполнение из-за desktop-структуры сайта.

Дополнительно 8 браузерных сценариев находятся в
`src/frontend/tests/generation_browser.test.html`. Они используют настоящий
DOM, события форм и DataTransfer, а задержки декодирования контролируются
тестовым Image. Проверяются drag-and-drop, очистка URL, сохранение предыдущего
фото, гонки загрузки и отключение обработчиков. Реальное декодирование
изображений отдельно проверяется через обычный выбор файла на странице.

Для повторного запуска на локальном dev-сервере из `src/frontend`:

```powershell
Copy-Item -LiteralPath tests/generation_browser.test.html -Destination public/__generation_regression.html
```

Открой `/__generation_regression.html` на адресе своего dev-сервера.
Ожидаемый результат: `8 passed, 0 failed`. После проверки удали только
временную копию:

```powershell
Remove-Item -LiteralPath public/__generation_regression.html
```

Тестовый стенд не должен попадать в production или в коммит папки `public`.

## Решения после визуального аудита

- Выбор по иллюстрациям расположен до персональных данных, чтобы первый
  экран соответствовал задаче подбора образа, а не выглядел длинной анкетой.
- Подписи вынесены из рамок карточек. Выбор обозначен радио-индикатором,
  границей изображения и подчёркиванием; состояние не зависит только от цвета.
- Убраны вводный абзац, повторяющиеся пустые значения и декоративное фото.
  Короткие подписи, форматы файлов и ошибки сохранены для однозначности.
- Проверены пустое состояние, выбор длинных названий, ошибки, заполненная
  сводка и нижняя часть формы. Основные desktop-размеры: 1200, 1280, 1440,
  1920 px. Адаптация всего сайта под телефон остаётся отдельной задачей.

Основания решений: [Carbon: Forms](https://carbondesignsystem.com/patterns/forms-pattern/)
о группировке полей и кратких подписях;
[NN/g: Aesthetic and Minimalist Design](https://www.nngroup.com/articles/aesthetic-minimalist-design/)
о приоритете существенной информации;
[W3C WAI: Labeling Controls](https://www.w3.org/WAI/tutorials/forms/labels/)
о сохранении понятных имён элементов управления. Это основания дизайна,
а не заявление о проведении пользовательского исследования или полном WCAG-аудите.
