# Фотографии и хранение результатов при интеграции

AI Core не требует определённого хранилища в вашем backend. Можно использовать
MinIO, другое объектное хранилище или HTTP-сервер, соблюдающий внешний контракт.

## Входные фотографии

- Для лица и полного роста нужны отдельные HTTP URL и реальные сроки `expires_at`.
- Согласуйте origin с поставщиком API. HTTPS, иной hostname или иной порт не заменяют
  согласованный HTTP origin.
- URL должны быть доступны AI Core без пользовательских cookies, дополнительных
  заголовков авторизации и HTTP-перенаправлений.
- Подписанные query-параметры допустимы; не изменяйте адрес после подписания.
- Остаток срока должен превышать `input_urls.min_ttl_seconds` из capabilities,
  с запасом на передачу запроса и возможный повтор.
- Имя `localhost` относится к машине вызывающей стороны; адрес, работающий только
  в браузере разработчика, может быть недоступен AI Core.

## Выходные изображения

Скачивайте `download_url` без изменения адреса до `results_available_until`.
Проверьте SHA-256, размер и полноту набора. Сохраните файлы в собственное постоянное
хранилище и только затем отправьте ACK. Защититесь от повторного сохранения по
`job_id` и `artifact_id`. При сбое скачивания или сохранения ACK не отправляется.

Файлы выдавайте своим пользователям с правилами доступа вашего приложения.
Не используйте временные `download_url` как постоянные ссылки галереи.
Формат берите из результата; текущие примеры API используют PNG, а не обязательный WebP.
