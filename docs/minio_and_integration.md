# MinIO, повторы и подключение сервисов

## Роль MinIO в проекте

MinIO хранит байты фотографий и предоставляет S3-совместимый HTTP API.
PostgreSQL хранит пользователей, задачи, состояния и ключи объектов. Запись Photo
не содержит изображение: она указывает, какой объект нужно получить из MinIO.

Бакет — контейнер объектов, здесь обычно `stylist`. Ключ — имя объекта, например
`albums/<album_id>/<processing_token>/look_00.png`. Символы `/` задают префиксы,
а не настоящие каталоги. Исходники лежат под `sources/`; для них настроено удаление
по lifecycle через один день. Результаты сохраняются постоянно под `albums/`.

Presigned URL — ссылка с подписью, которая разрешает конкретную операцию над
конкретным объектом до истечения срока. Она не делает бакет общедоступным.
Параметры подписи и адрес ссылки нельзя произвольно менять после подписания.
Ссылка действует независимо от JWT приложения до своего истечения, поэтому
backend сначала проверяет владельца альбома, затем выдаёт ссылку браузеру.

Существующие материалы: `docs/docker_setup.md` — Docker и порты;
`docs/generation_pipeline_architecture.md` — состояния, ключи, подписи и доставка.
Этот документ объясняет повторы и порядок подключения всей связки.

## Почему ошибка MinIO не всегда является S3Error

Есть два уровня отказа. Если сервер ответил S3-ошибкой, SDK получает S3Error,
например AccessDenied или SlowDown. Если соединение не установилось, DNS не
разрешился или ответ не пришёл вовремя, HTTP-транспорт urllib3 выбрасывает свои
исключения. MaxRetryError означает, что транспорт исчерпал попытки, но не означает,
что сама генерация ИИ закончилась неудачно. Он не наследуется от OSError.

Поэтому обработчика только для S3Error и OSError было недостаточно: транспортная
ошибка ошибочно становилась окончательным FAILED. В `retry_policy.py` теперь
отдельно классифицируются ошибки транспорта, SDK и AI Core.

| Событие | Решение при сохранении готовых результатов |
| --- | --- |
| Ошибка соединения urllib3, таймаут, MaxRetryError | Оставить DOWNLOADING для recovery |
| MinIO ServerError 5xx, не-XML ответ 502/503 | Повторить позднее |
| S3 SlowDown, InternalError, ServiceUnavailable, RequestTimeout | Повторить позднее |
| S3 AccessDenied, NoSuchBucket без серверного 5xx | FAILED; исправить права или конфигурацию |
| Неверная контрольная сумма, недопустимое число результатов | FAILED; результат нельзя подтверждать |

Бесконечный плотный цикл повторов не используется. SDK имеет таймаут соединения
3 секунды, чтения 15 секунд и до двух повторов с небольшой задержкой. Это таймауты
отдельных сетевых операций, а не жёсткая граница времени загрузки всего файла.
После исчерпания транспортных попыток задачу повторяет recovery. Его интервал по
умолчанию 30 секунд; время обработки прохода добавляется к интервалу. Общий срок
задачи по умолчанию 24 часа, после него recovery завершает задачу ошибкой.

## Как повторять без повреждения данных

PostgreSQL является долговременным источником состояния. Если процесс backend
перезапустится, незавершённые задачи остаются в БД. Оперативная очередь ускоряет
обработку, но не является единственным местом хранения задания.

Работник получает lease — временное право на обработку с уникальным токеном.
Heartbeat продлевает lease. Сохранить фотографии и окончательный статус может
только владелец действующего токена. Старый работник после потери lease не должен
перезаписать результат новой попытки.

Каждая попытка пишет в свой префикс. При сбое её неподтверждённые файлы удаляются
после проверки ссылок в PostgreSQL; при недоступной БД удаление откладывается.
Успешные фотографии и COMPLETED фиксируются одной транзакцией. ACK для AI Core
отправляется только после commit: подтверждение до сохранения могло бы разрешить
ИИ удалить единственную копию результата.

Транзакция PostgreSQL не включает MinIO и AI Core. Это несколько независимых
систем, поэтому общая атомарность достигается порядком действий, повторяемостью,
проверкой владельца и очисткой временных объектов, а не одной SQL-транзакцией.

## Первая отправка в AI Core

До HTTP-запроса backend сохраняет альбом и параметры отправки, включая подписанные
URL, expires_at и количество результатов. При 429, 5xx или сетевой ошибке задача
теперь остаётся незавершённой, обычно VALIDATING, освобождает lease и возвращает
клиенту 202 с generation_id и status_poll_url. Ошибка записывается для диагностики.
Recovery повторяет отправку. При окончательной ошибке вроде 400 INVALID_REQUEST
задача остаётся FAILED и запрос возвращает ошибку.

При повторе используется тот же Idempotency-Key и идентичное тело. Даже если ИИ
принял первый запрос, а ответ потерялся, повтор должен вернуть прежний job_id,
а не создать вторую генерацию. Новый пользовательский POST по-прежнему создаёт
новую генерацию; разные пользовательские запросы не объединяются.

Идемпотентность должна быть реализована AI Core согласно его договору. Подписанные
URL имеют конечный срок: повтор не переподписывает их автоматически, потому что
это изменило бы тело запроса с тем же ключом. Длительный простой может исчерпать
TTL ссылок раньше общего срока задачи. Это ограничение нужно учитывать при выборе
TTL и доступности ИИ. Текущий recovery не планирует отдельное время по Retry-After:
он повторяет попытки периодически.

Если не удалось сохранить исходные фотографии, альбом ещё не создан. Этот более
ранний этап по-прежнему возвращает 502; фонового задания для восстановления нет.

## Адреса и порты

| Кто обращается | Адрес при стандартном локальном Compose |
| --- | --- |
| Браузер к сайту и API через nginx | http://localhost:8080 |
| Браузер напрямую к Swagger backend | http://localhost:8000/docs |
| Проверка PostgreSQL и бакета MinIO | http://localhost:8000/health |
| Backend и AI Core к MinIO внутри Docker-сети | http://minio:9000 |
| Браузер к S3 API MinIO | http://localhost:9000 |
| Браузер к консоли MinIO | http://localhost:9001 |

`localhost` внутри контейнера означает этот контейнер. В браузере телефона он
означает телефон. Поэтому внутренний адрес MinIO и публичный адрес для браузера
разные. Для телефона MINIO_PUBLIC_ENDPOINT должен содержать доступный адрес
компьютера или сервера, а не localhost. При HTTPS-сайте файлы также нужно выдавать
через HTTPS, чтобы браузер не блокировал смешанный контент.

Маршрут `/` у backend не определён, поэтому 404 по http://localhost:8000/ нормален.
Это API-сервис, а не главная страница сайта. Сайт открывается через nginx на 8080.

## Порядок сквозного подключения

1. **Поднять инфраструктуру.** Проверить `docker compose ps`, затем `/health`.
   В Compose миграции PostgreSQL применяются перед запуском uvicorn. Сама сборка
   образа не изменяет схему БД. Команда запуска: `docker compose up -d --build`.

2. **Подключить AI Core к backend.** Собрать три образа из `ai-stylist-core`:
   artifact-service, main-orchestrator и public API, затем запустить
   `docker compose -f docker-compose.yml -f docker-compose.ai-core.yml up -d`.
   Overlay подключает backend к `http://ai-core-api:8000`, публикует API на
   `127.0.0.1:8001`, artifact-service на порту `18081` и orchestrator на
   `127.0.0.1:18180`. `AI_CORE_ARTIFACT_PUBLIC_BASE_URL` должен содержать адрес
   хоста, достижимый и из контейнеров, и из native MPS worker (обычно LAN IP).
   Пароль PostgreSQL и стабильный Fernet key обязательны.
   `AI_CORE_WORKER_URLS` обязан содержать все девять стадий пайплайна. Оркестратор
   возвращает `503` и перечисляет `missing_worker_stages`, если artifact-service
   недоступен или хотя бы одна стадия не настроена. Проверить `/health/ready` и
   `/v1/capabilities` AI Core.

3. **Разрешить AI Core скачивать исходники.** Origin `http://minio:9000` должен быть
   разрешён в настройках AI Core и доступен службе, которая действительно импортирует
   фотографии. Важны схема, имя и порт. Проверять нужно из контейнера импортирующего
   сервиса, а не только из браузера разработчика. MINIO_PRESIGNED_TTL должен превышать
   актуальный min_ttl_seconds и оставлять запас на передачу и очередь. Сейчас TTL
   backend по умолчанию 3600 секунд. Переменную нужно передать именно процессу backend;
   добавление произвольной переменной в корневой .env не передаёт её контейнеру, если
   она не указана в environment Compose.

4. **Соединить форму фронта.** Передать два реальных File через FormData, добавить
   Authorization: Bearer с пользовательским JWT. Не устанавливать Content-Type
   вручную: браузер сформирует multipart boundary. Изображения preview/object URL
   не заменяют сами файлы. При вызове через `/api/v1` nginx сохраняет единый origin.

   | Значение формы | Поле REST backend |
   | --- | --- |
   | occasion | situation |
   | style | styles |
   | shoe | shoes |
   | mood | impressions |
   | male / female | gender: m / f |
   | два выбранных файла | face_photo / body_photo |

   Возраст и рост тоже передаются. Сейчас фронт допускает 1–120 и 80–240, backend
   допускает 18–100 и 120–230: ограничения требуется согласовать отдельно.

5. **Показать ход задачи.** После 202 сохранить generation_id и опрашивать
   status_poll_url с паузой. VALIDATING может означать ожидание повторной отправки,
   QUEUED/PROCESSING — работу ИИ, DOWNLOADING — сохранение результатов. COMPLETED
   даёт album_id; FAILED завершает ожидание и показывает ошибку. 401 требует входа,
   временная сетевая ошибка опроса не должна создавать новый POST генерации.

6. **Открыть результат.** Получить GET /api/v1/albums/{album_id} с JWT и отобразить
   пять URLs из photos. Проверить загрузку изображений в браузере того устройства,
   с которого используется сайт. После истечения подписанных ссылок заново получить
   альбом, чтобы backend сформировал новые ссылки.

7. **Проверить реальную интеграцию.** Пройти регистрацию/вход, отправку двух фото,
   получение job_id, обработку ИИ, скачивание и SHA-256, сохранение пяти Photo,
   COMPLETED, ACK и открытие всех пяти изображений. Отдельно проверить временный
   отказ MinIO, 503 ИИ и перезапуск backend во время задачи. Делать это на тестовых
   данных и тестовой среде; unit-тесты с заглушками не подтверждают реальную сеть.

На macOS FLUX worker запускается нативно на `127.0.0.1:18083` с MPS. Overlay
обращается к нему через `host.docker.internal:18083`, а worker получает artifact
URLs из `AI_CORE_ARTIFACT_PUBLIC_BASE_URL`. Этот origin нужно также разрешить в
`GENERATION_ARTIFACT_ORIGINS`. Публикацию порта `18081` следует ограничить
локальной доверенной сетью firewall. Остальные обязательные processing workers должны
быть добавлены в `ORCHESTRATOR_WORKER_URLS` до полного product E2E; отсутствие
этих адресов означает ожидающее задание, а не успешную production-конфигурацию.

## Проверки изменений

`tests/test_dependency_retries.py` проверяет реальные классы исключений MinIO SDK
на стадии upload_bytes, отсутствие commit/ACK при сбое, окончательные ошибки прав
и replay первой отправки после 429, 500, 503 и потерянного ответа. При replay
проверяются неизменность тела, ключа и единственность альбома.

Официальные материалы: [MinIO Python SDK](https://github.com/minio/minio-py),
[исключения urllib3](https://urllib3.readthedocs.io/en/stable/reference/urllib3.exceptions.html).
