# DEF-1 — постоянные ошибки БД

Автор — Шульга Иван Петрович. Задача #142, BACK-13.

Классификатор принимал любой SQLAlchemyError за временный отказ.
IntegrityError, ProgrammingError и DataError теперь возвращают False.
При connection_invalidated сохраняется True: потеря соединения проверяется первой.

## Проверки

До исправления регрессия дала 3 failed, 4 passed. После исправления локальный
полный набор дал 322 passed, 5 skipped. Пропуски требуют тестового PostgreSQL.
Новый test_retry_policy_regression.py автоматически включён в существующий
Backend Tests, выполняющий pytest tests с PostgreSQL на Python 3.12.

Из корня проекта в Git Bash:

```bash
./.venv/Scripts/python.exe src/backend_core/labs/diagnostics/run.py
./.venv/Scripts/python.exe src/backend_core/labs/diagnostics/run.py before
./.venv/Scripts/python.exe src/backend_core/labs/diagnostics/run.py after
./.venv/Scripts/python.exe -m pytest -q src/backend_core/tests
```

Диагностика выполняет по 200 повторов пяти случаев с tracemalloc.
Режим before намеренно заканчивается AssertionError и кодом 1.
Режим after должен вернуть код 0. Снимок ошибочной версии policy_before.py
используется только стендом. Новые результаты пишутся в local-diagnostic.json,
который исключён из Git. Сохранённая серия — diagnostic.json в этой папке.

## Область доказательств

Исключения создаются в памяти. Tracemalloc измеряет Python-выделения на исполненных
путях. Нативные ресурсы и настоящий сетевой отказ PostgreSQL не проверяются.

Миллс по протоколу ПР2 на основе 791e71c5: M=5, m=5, n=0. N̂=0, R̂=0.
DEF-1 найден другим набором и в n не входит. Нулевое значение не доказывает
отсутствие естественных ошибок. Места пяти мутаций известны, слепой поиск нарушен.

Независимое review подтверждается только реальным решением рецензента.
