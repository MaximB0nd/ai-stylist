# Подключение frontend к backend_core

Frontend обращается к `/api/v1` на том же origin, откуда открыт сайт.
Nginx уже направляет `/api/` в `backend_core:8000`, остальные страницы — во frontend.
Не нужно подставлять IP backend в JavaScript, настраивать CORS для этих запросов
или открывать frontend непосредственно на внутреннем порту 5091.

## Запуск

Из корня проекта:

```bash
docker compose up -d --build backend_core frontend nginx
```

Compose поднимет также PostgreSQL и MinIO; миграции выполняются командой запуска backend.
Сайт на этом ПК: `http://localhost:8081`, если в корневом `.env` задан `NGINX_PORT=8081`.
С другого устройства: `http://<LAN-IP backend>:8081`.

Для просмотра фотографий с других устройств задайте в корневом `.env`:

```dotenv
MINIO_PUBLIC_ENDPOINT=<LAN-IP backend>:9000
MINIO_AI_ENDPOINT=<LAN-IP backend>:9000
AI_CORE_URL=http://<LAN-IP AI>:<порт AI>
```

`MINIO_ENDPOINT=minio:9000` остаётся внутренним адресом Docker.
Подробности настройки двух ПК и AI Core: [LAN-интеграция](lan_integration.md).
IP Windows можно посмотреть командой `ipconfig`, раздел Wi-Fi, IPv4 Address.

## Подключённые сценарии

- Регистрация и вход: POST `/auth/register`, `/auth/login`; профиль: GET `/auth/me`.
  Bearer JWT хранится в существующем localStorage `aiStylistAuth`.
  Выход очищает локальную сессию, без отзыва stateless JWT на сервере.
  Временная ошибка загрузки профиля больше не удаляет действующий токен; 401 завершает сессию.
- Генерация: POST `/generations` как multipart с реальными выбранными файлами
  `face_photo` и `body_photo`. Поля интерфейса occasion/style/shoe/mood сопоставлены
  situation/styles/shoes/impressions, female/male — f/m. Рост согласован с backend: 120–230.
  Конвертация изображений остаётся на backend. Повторный клик во время отправки блокируется.
- Принятый generation_id сохраняется в query URL страницы генерации. GET
  `/generations/{id}/status` выполняется последовательно раз в 3 секунды, без
  параллельных опросов. Refresh продолжает ожидание, а не повторяет POST.
  COMPLETED открывает `/album/{album_id}`, FAILED показывает ошибку.
  При потере ответа POST автоматического повтора нет: он мог уже создать задачу.
- Главная и галерея: личные альбомы из GET `/albums`, детали через GET `/albums/{id}`.
  Детали загружаются максимум четырьмя запросами одновременно; на главной — первые три альбома.
  Демонстрационные ссылки на несуществующие личные альбомы удалены.
- Альбом: фотографии из API, полноэкранный просмотр с переключением и Escape.
  Имена и сообщения сервера вставляются как текст, а не HTML.
- Отзывы: POST `/feedback` с name/email/comment, JWT текущего пользователя,
  HTML-валидация обязательных полей и длины плюс валидация backend.
  При ошибке текст сохраняется, при успешном сохранении поле сообщения очищается.
- Настройки темы и анимации остаются локальными: API хранения настроек отсутствует.
  Редактирование профиля, удаление/переименование альбомов и избранное не добавлены:
  соответствующих публичных методов backend нет.

Запросы страниц отменяются при переходе, слушатели не накапливаются.
Веб-интерфейс требует входа для личных данных; backend проверяет принадлежность альбомов.
FAQ и описание передачи фотографий обновлены под фактическую отправку в AI Core.

## Проверки

Из `src/frontend`:

```bash
npm run test:unit
python -m unittest discover -s tests -p 'test_*.py'
```

Для Python используйте штатное окружение проекта (Python 3.14 и зависимости uv),
либо собранный Docker-образ frontend.

`tests/backend_browser.cjs` — дополнительная браузерная проверка на запущенном frontend.
Требуется Playwright; по умолчанию используется установленный Microsoft Edge.
`FRONTEND_TEST_URL` задаёт адрес frontend (по умолчанию http://127.0.0.1:15091),
`PLAYWRIGHT_CHANNEL` — канал браузера. Запуск: `node tests/backend_browser.cjs`.
Проверка подменяет ответы `/api/v1` тестовыми данными: вход, пять фото, галерея,
крупный просмотр, ошибка и повтор отзыва, multipart, ожидание и refresh без повторного POST,
профиль и выход. Это проверка UI и контракта, а не реальной модели ИИ.

Перед интеграцией с ИИ нужен отдельный реальный прогон: регистрация → отправка двух
фото → завершение генерации → пять сохранённых фото → открытие их из браузера.

## Результаты проверки реализации

24 JavaScript-теста и 38 Python-тестов страниц прошли. Сценарий
`backend_browser.cjs` прошёл в Microsoft Edge на временном Docker frontend с
тестовыми ответами API. Docker-образ frontend собирается.

В дополнительном старом `generation_browser.test.html` остаются три визуальных
несоответствия: ожидание плейсхолдера выбора, заполнение колонки миниатюрой и
поля вокруг предпросмотра. Те же три ошибки воспроизведены с исходным
`generation.js` из HEAD; они не вызваны интеграцией API. Эти стили в задаче не менялись.
